# Yew Harness 对外介绍

版本 0.46（2026-11-21）。官网产品库、README、App Store 描述和各渠道介绍 Yew Harness 时以本文为准；能力有变化先改这里，再改各处。改了以后把提交号告诉平台组，由它同步官网产品库的条目。依据是产品蓝图（Tenon-AI 的 `docs/products/yew/blueprint.md`）第一至五节、`~/memory/session-engineering.md`，以及产品规范 1.8、14.1–14.3。

## 一、定义

「AI 原生的多 Agent 工作台」 / "An AI-native multi-agent workbench"（2026-11-08 定稿，规范 1.8）。

只用这一句，不另写版本，不加修饰。产品库的 `kind`、页眉页脚等处描述 Yew Harness 是什么的短语，也用这一句。

**名字**：产品叫 Yew Harness，中英文都这样写，不另起中文名，也不简称 Yew；单说 Yew 指红发女孩（2026-11-18 创始人定，蓝图第十二节）。npm 包 `@tenonai/yew`、命令 `yew` 这些技术名字照旧，写安装和命令时照原样写。

## 二、一段话简介

定义之后接这一句。README 第二段、关于页定义之后、商店描述的开头都用它。官网的摘要和 meta description 按产品页的主张另写，见第六节。介绍要短：会话怎样分主次、信件、手机审批这些细节放在产品页的主张里，不塞进简介。

> 按 Session Engineering 的做法组织 Agent 会话：你只对接主对话，要你授权和决定的事都汇到审批中心。

> Agent sessions organized the Session Engineering way: you deal only with the main conversation, and everything that needs your approval or decision comes to the approval center.

**讲给谁**：一个人带一组 Agent 会话做事的开发者和一人公司。

## 三、理念

Yew Harness 的特点不在单个会话多能干，而在一组会话怎样组织、人怎样和它们打交道。写文案时按下面几条取舍，不必逐条写出来：

1. **Session Engineering**：一个 Agent 已经能独立做完一件事，会话一多，限制就变成了人能跟住几个会话。Session Engineering 围绕这个限制组织工作：事情怎样分给会话，会话之间怎样交接，人每次要重新读多少东西。Yew Harness 是照这套做法做的工作台。做法的来历见官网博客的两篇 Session Engineering 文章，详情页可以链接过去。
2. **主次结构**：主对话统筹，替你分派、转达、汇总回报，并维护审批中心；常设会话按团队各管一块事；任务会话为一件事开设，做完回报。结果用信件一级级回到主对话。
3. **人只处理要人处理的事**：人管方向、决定和授权。方向在主对话里说一句；要你授权的操作、要你回答的问题和要你定的事都汇到审批中心。其他会话不用逐个进去看，想看时随时能点开。
4. **结构由 Yew Harness 的代码保证**：回报自动寄回请求方，决定标明出自你本人，会话的命令碰不到 Yew Harness 自己的数据和你不让会话读的目录，对外发布、以你的名义对外发消息、改生产环境这类做错了收不回的事在默认和自动方式下都由你本人点头，会话之间的信有额度和转发次数限制。这些由 Yew Harness 执行，不靠提示词让模型自觉。
5. **在你的电脑上运行**：会话在本机的 Yew Harness 服务里运行，网页关了也照常干活；会话、信件和设置存在你的电脑上，Yew Harness 不收集任何数据。每个会话单独选服务商和模型，不绑定任何一家。

## 四、能写的能力

已经实现的能力都能写，发布没发布写法一样：直接写能做什么，不加「目前」「暂未」「即将」。能不能下载看官网有没有入口（Yew Harness 的产品页有安装命令、源代码和安卓版的下载，iPhone 版还没上架），文案里不逐句交代；没实现的不写，也不写成计划。写之前对照[更新记录](../CHANGELOG.md)：已发布的记在各版本下，已实现、还没发布的记在「未发布」下。

- **已发布**（1.0.0，2026-11-15 开源，当时叫 Jig；1.3.0 起叫 Yew，1.5.0 起叫 Yew Harness，npm 包仍是 `@tenonai/yew`）：会话与团队、工作区；三种授权方式和「总是允许」；读写文件、命令、搜索、抓取网页和任务清单；上下文自动压缩；会话之间的信件；主对话和它替你改设置；审批中心（授权卡、提问卡、决定卡、待放行的信）；任务会话；`yew serve`、`yew send`；网页界面的中英文和深浅色；侧栏底部的 Yew（红发女孩）用气泡说眼下最要紧的一件事，说的是一件事或一个会话时点一下直接过去，打开时有一秒左右的开场，列出真实的启动步骤（1.4.0）；设置窗口和「个性化」（主题、语言、界面里的 Yew 和开场）、系统沙箱（macOS 和 Linux）、会话读不到的目录（1.6.0）；Mac 应用、默认 / 自动 / 跳过三种授权方式和审批、沙箱外命令的外层保护、浏览器默认连用户自己的 Chrome、自带联网搜索、hooks（1.7.0）；版本与更新：关于页写当前版本，后台跑的代码比装着的旧时提醒并一键重启，用 npm 安装的每天查一次新版本（可关）、一键更新，安卓查 Gitee 上的新版本（1.8.0）；消息附件与离线读 PDF、多目录工作区与分级放行域名、每次新开任务会话的定时任务、自动授权的跨会话溯源、原地开启新上下文与输入框的 `@`、`/` 触发器、手机端对齐新的审批分层（1.9.0）。
  - 授权和审批：每个会话选一种授权方式，只管「这一步能不能执行」：默认方式下常用的操作直接执行、有风险的先问；自动方式下本来要问的先交给一次单独的模型检查，它只看用户亲自写的话；做错了收不回的操作（对外发布、以用户的名义对外发消息、往外发数据、远程主机和生产环境、删工作区外的文件）不交给检查，直接问用户；跳过方式下什么都不问，这些操作也直接执行，在记录里标出有风险的调用，只有提高花费上限还问。审批是会话交给用户定的事：提问、决定卡和回复末尾留下的问题，尽量做成选择题，哪种方式都不跳过。写的时候说明：自动方式只认得出看得见的对外操作，脚本里发出去的认不出；跳过方式下 Yew Harness 不再拦，哪些事先问用户取决于写在会话职责和项目说明里的要求，由会话自己来问；跳过方式下开着电脑操控时，它能替用户点下等着的卡。不写「三种方式下都要你决定」（1.10.2 及之前是这样，之后改了，见修改记录 0.44）。
  - 沙箱外的命令：到沙箱外跑的命令仍有一层外层保护，读写不了 Yew Harness 的数据目录和用户不让会话读的目录，拉不起保护之外的程序，写不了会自己运行的启动文件和仓库设置。不写成「绝对安全」。
  - Mac 应用：`yew app install` 在「应用程序」里放 Yew Harness 应用，界面在它自己的窗口里，Dock 上有图标，角标是审批中心里等着的件数；关掉窗口或退出应用，Yew Harness 照常在后台运行。写的时候说明它随 npm 包装上，还没有可以直接下载的安装包，也没有 Windows 版。
  - 联网搜索：有 DeepSeek 的密钥就能搜，用 DeepSeek 官方的搜索接口，不用另配，按次收费、记在用户的 DeepSeek 账上；也可以存博查、Tavily、Brave 的密钥，存了就先用它们。DeepSeek 搜索 11-19 用真实密钥试通过；博查、Tavily、Brave 的真实接口还没调通过，不点名写这三家。
  - hooks：照 Claude Code 的写法，在会话开始、用户发消息时、工具调用前后和会话停下前跑用户自己的命令，能拦下这一步或给会话补一句，不能替用户放行或批审批。配置在数据目录的 `hooks.json`，项目仓库里带的 hooks 不读。
  - 系统沙箱（macOS、Linux）：会话的命令和用户自己加的 MCP 服务器在沙箱里运行，用的是 Anthropic 开源的 sandbox-runtime（macOS 上是 Seatbelt，Linux 上是 bubblewrap）。沙箱里读写不了 Yew Harness 的数据、读不到钥匙串，只能写工作区、临时文件夹和沙箱自己的缓存，联网只放行常用的包管理源、代码托管网站和配了密钥的模型服务商，连别的网站先问用户；要在沙箱外跑的命令默认方式下每次都问，自动方式先检查，跳过方式不问、仍在外层保护里运行。Linux 上只在容器里跑过测试，写的时候不说「实测」；不写「绝对安全」这类说法。
  - 会话读不到的目录：用户在设置里列出放密钥、私人笔记的文件夹，会话的文件工具、沙箱里的命令和沙箱外的命令都读不到。
- **已实现、还没发布**：
  - 手机审批：手机应用（iPhone、安卓）扫码和 Mac 配对，经中继连接，端到端加密，中继只转发密文。在手机上允许或拒绝操作、回答提问、做决定、放行或拒收暂存的信；也能看会话记录和信件、给会话发消息、让干活的会话停下。
  - 定时任务：按时以定时任务的名义给一个常设会话寄信，会话无人值守地做完，回报寄给主对话。讲主次结构时可以带上。
  - 每日费用上限：给一个会话或全部会话设每天最多花多少美元（按服务商的价格估算），到 80% 提醒，到上限会话停下，点继续当天再给同样多的额度。提醒现在写在会话记录里，不写「推送提醒」。
  - 开机启动：`yew service install` 让 Yew Harness 在登录后自动启动，macOS 和 Linux 都支持。
- **写手机时**：会话仍在 Mac 上的 Yew Harness 里运行，手机经中继连到这台 Mac，所以 Mac 上要开着 Yew Harness。安卓版已发布（1.0.1 起），安装包在 GitHub 和 Gitee 的 Releases 里，由公司签名；介绍下载时只指向官网 Yew Harness 页的「安卓版」一节（`https://tenonai.cn/zh/products/yew/#android`），那里有两个下载入口和签名证书指纹，不直链安装包文件。iPhone 应用还没上架，之后经 TestFlight 和 App Store 发布，不写成可以下载。安卓版和 iPhone 版不同的地方见安卓版文档（Tenon-AI 的 `docs/products/yew/android.md`）第 5 节：安卓不用推送服务，打开通知后由应用在后台保持到中继的连接，系统会显示一条常驻通知。安卓版只在模拟器上走查过，真机和真实中继上的配对、通知没验过，写的时候不说「实测」。API Key、配对和移除手机只在 Mac 上操作。
- **写模型时**：模型接入用开源库 pi-ai；Agent 循环、工具和权限是 Yew Harness 自己写的，所以不写「基于 Pi Agent」。设置里列出 pi-ai 内置的 33 个服务商入口，来自 23 家（同一家的不同地区、套餐分开列），还能添加兼容 OpenAI 接口的服务商或本机运行的模型。每个会话单独选，默认 DeepSeek。
  - 通知：审批中心有新的待办、会话出错、任务做完、费用到上限时通知手机，内容端到端加密。中继已上线（`wss://relay.tenonai.cn`）。iPhone 的通知只在模拟器上验到 Apple 接受为止，真机上没验过，写的时候不说「实测」。
  - 产物：会话把文档、页面、数据和图表存成产物，有版本，在电脑和手机上看；HTML 页面在隔离环境里显示。
  - 技能和记忆目录：读 `~/.claude/skills` 等位置的技能（SKILL.md）和你指定的记忆目录，现有的配置不用搬。
  - MCP：按通行的 `mcpServers` 写法配置，支持本机程序和网址两种，每个工具第一次用先问你；会发送、发布或删除东西的工具（按工具名和服务自己的标注判断）每次都问，不能设成总是允许；跳过方式下都不问。
  - 浏览器和电脑操控：Yew Harness 自带两个 MCP 服务。浏览器默认经 Playwright 的 Chrome 扩展连用户自己的 Chrome（要先装上扩展，第一次使用时在 Chrome 里同意连接、选给它用的标签页），用的是用户已有的登录，也可以在设置里改成单独的 Chrome 窗口，会话可以打开网页、点击、填写；电脑操控可以截屏、动鼠标、敲键盘。默认授权方式下每次调用先问用户，电脑操控的点击和输入，以及连用户自己的 Chrome 时浏览器在页面上的操作（点击、输入、打开网址、运行脚本等），每一次都要确认，不能设成总是允许；跳过方式下都不问；可以在设置里停用。写的时候说明它们由开源的 Playwright MCP 和 computer-use-mcp 提供，第一次使用要联网安装；截屏和网页内容会作为工具结果发给用户所选的模型服务商；连用户自己的 Chrome 时，会话在页面里运行脚本能读到网站允许脚本读取的 Cookie。
  - 分叉和回溯：会话可以带上自己的记录开一个任务会话，任务说明可以写短；你可以从任意一条回复或你的任意一条消息分叉出新会话，也可以把对话回溯到某一处重来。回溯只撤回对话，不撤回已经改的文件和执行过的命令。
  - 消息下的操作：每条消息和回复下面，鼠标移上去显示时间、复制、回溯和分叉。
  - 助手：会话可以把一件独立的事交给助手去查，只拿回结论。助手只能读和查，不能改东西，几个可以同时跑。
  - 常用 MCP 服务：GitHub、Gitee、Context7、Notion、Sentry 填上令牌就能添加；Linear、Vercel、Gmail、Google 日历、Google 云端硬盘在浏览器里登录（Google 的几个要用户自己在 Google Cloud 建客户端，目前在 Google 的开发者预览阶段）。要求登录的远程 MCP 服务都能在 Yew Harness 里登录。
  - 悬浮的 Yew：Yew 不再站在侧栏底部，悬浮在窗口上，可以拖到窗口里任何地方，气泡照旧说眼下最要紧的一件事，点一下直接过去；侧栏底部只留设置。
  - 数据导出：`yew export` 把会话导出成 Markdown，其余导出成 JSON；设置的「数据管理」里也能导出，还能看数据目录占了多少、清理临时文件。
  - 用量：「用量」页画出最近 30 天每天的费用，今天花了多少、离每日上限多远，某一天每个会话的费用和 token。费用按服务商的价格估算，写的时候说「估算」。
  - 会话关系：「会话关系」页用一张图列出全部会话，谁开了谁、最近 24 小时的信从哪到哪、各自的状态。
  - 会话进度和等待时间：会话在干活时写这一轮读了几个文件、改了几处、跑了几条命令、用了多久；审批中心每一项写明等了多久。
  - 设置：MCP 服务、技能、搜索服务的密钥、中继地址、通知哪几类事、新会话的默认授权方式和工作区、登录时启动和「应用程序」里的 Yew Harness 应用，都能在设置里改，不用命令行。技能只能停用和启用，不能在 Yew Harness 里编辑或安装。
  - 服务商的连接测试：设置的「服务商与密钥」里可以测试一个服务商连不连得上、多久开始回答。Yew Harness 不显示服务商账户的余额。
  - 消息附件与离线 PDF：网页端支持选择、粘贴、拖入图片、PDF 和文本文件随消息发送，手机端支持拍照/相册附带图片并查看原图；图片存放在数据目录的 `attachments/`，按所选模型是否支持视觉自动发图或降级为说明；`read` 和 `read_attachment` 工具使用本地离线的 PDF 引擎读取文字和目录，并支持按页码范围渲染扫描页。
  - 多目录工作区与分级沙箱域名：单个会话除主工作区外，可配置多个「只读」或「可读写」附加目录（自动同步到文件权限与系统沙箱，始终避开密钥和会话读不到的目录）；系统沙箱支持全局放行域名和会话级放行域名。
  - 双模式定时任务：定时任务除了按时向常设会话寄信，也支持每次触发新开一个隔离的任务会话执行，回报归属会话和主对话，并在无报错无待审批时自动归档。
  - 自动授权跨会话溯源：在自动方式（`review`）下，模型检查器直接读取数据库中经过服务端核验的决定卡和主对话里用户亲自写下的原话（可在默认设置中关闭主对话溯源），不以其他会话的转述作为依据。
  - 常设会话原地开启新上下文与统一触发器：常设会话可以在保留上方全部历史与搜索索引的前提下，原地开启新上下文（可选带交接摘要或清空开始）；输入框支持 `@` 搜索会话名与工作区/附加目录文件，行首 `/` 触发已启用的技能与 `/compact`、`/renew`。
  - 手机端对齐：iPhone 和安卓应用对齐 1.7.0+ 的审批/授权分层，展示审批原因、自动检查拒因、文件改动 diff、管理变更步骤、沙箱内运行列表、`acts-as-you` 二次确认和工具自动放行/风险标记，并支持收发消息图片。
- **没实现，不写**：可下载安装的桌面应用、Windows。安装命令是 `npm install -g @tenonai/yew`，以 npm 上实际能装为准。
- **A2A**：按创始人 11-11 的定稿，指会话之间的异步信箱，也就是 Yew Harness 的信件。Yew Harness 没有实现 A2A 协议，不写成支持或兼容 A2A 协议。
