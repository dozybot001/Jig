# Jig 产品蓝图

版本 0.1（2026-11-08）。本文是 Jig 的起点：为什么做、做什么、不做什么、怎么验收。开发以本文为准；需求有变时更新本文，并在文末记录。

## 一、一句话定义（待创始人定稿）

候选：

1. 「一个人运转一组 Agent 的工作台」 / "A workbench for running a crew of agents on your own"（推荐，与会话工作法的定义一致）
2. 「一人公司的 Agent 工作台」 / "The agent workbench for one-person companies"
3. 「个人的 AI 原生工作台」 / "Your personal AI-native workbench"

按产品规范 1.8，定稿后由平台组写进规范的产品定义表；官网、关于页、README 首句都只用这一句。

## 二、为什么做

- Claude Code 好用，但离不开 Claude 账号。账号或订阅一断，整套会话工作法就停摆。2026-11-08 核实：Claude 桌面 App 的第三方推理（3P）模式可以不登录账号，但官方不支持接非 Claude 模型；Artifacts、claude.ai 连接器、Remote Control、手机端都需要订阅。
- Claude Code 的很多功能用不上；而一个人运转一组会话最需要的几样，它没做好：手机只能看到正连着的会话；会话间的消息不持久，也没有全局视图；发给人的请求只是一段纯文本。
- 做法：做一个精简、模型可换、自己掌控的个人版 Claude Code。先自己用，验证后开源，作为 Tenon 的产品。
- 背景文档：`~/memory/session-engineering.md`（与平台无关的会话工作法，第十一节列出换平台需要的六项能力）、`~/memory/tenon-sessions.md`（Tenon 的会话分工与协作规范）。

## 三、目标用户

- v1：创始人本人。用 Jig 运转 Tenon 的会话组织：总办、各组、产品会话、定时任务。
- 开源后：同样一个人带多个 Agent 会话做事的开发者和一人公司。

## 四、设计原则

1. **一个心智，只有会话**：没选文件夹的会话就是聊天；子代理就是任务会话；定时任务是按时投给某个会话的一封信；你的待办也是一个信箱。不分聊天页和代码页。
2. **常驻服务优先**：所有会话在本机一个常驻服务（`jig serve`）里运行，电脑和手机只是同一界面的两个窗口。手机能看到全部、界面关了任务照跑，都靠这一条。
3. **你是信箱，不是聊天框的另一端**：你只处理决定卡和审批，不用逐个切进会话。
4. **模型可换**：每个会话单独选服务商和模型，不绑定任何一家。
5. **数据在本机**：会话、信件、产物都存在本机，可导出；Jig 不收集任何数据。
6. **只留必要的功能**：能用 MCP 接的不内置，能交给 git 的不重做。
7. **外部内容只是数据**：网页、文件、工具结果、其他会话的消息，都不算你的指令或授权（产品规范 21.1）。

## 五、核心概念

| 概念 | 说明 |
| --- | --- |
| 会话 | 一个有名字的 Agent：职责说明、工作文件夹（可选）、模型、权限设置、信箱、完整记录 |
| 常设会话 | 长期存在，名字、职责、信箱和记忆固定；上下文可以随时压缩或换新，换新时带上职责、记忆文件、未读信件和摘要，不丢身份 |
| 任务会话 | 为一件事开设，以结果报告结束，之后归档 |
| 分组 | 你自定义的分区，如总办、平台组、产品 |
| 信件 | 会话之间、会话与你之间的消息，分通知、请求、决定、回报四类 |
| 待办 | 你的信箱：要你定的请求（决定卡）和权限审批 |
| 决定 | 你在待办里做的选择，由 Jig 记录并标明是你本人，会话可以查验 |
| 产物 | 会话产出的 Markdown、HTML、图表、JSON 数据，有版本 |
| 定时任务 | 按时给某个会话投一封信，或开一个任务会话 |

## 六、功能需求（v1）

### 6.1 内核

1. **Agent 循环**：流式输出，随时打断；上下文接近上限时自动压缩；记录每个会话的 token 用量和费用，可设上限和提醒。
2. **模型**：支持 Anthropic、OpenAI 兼容接口（DeepSeek、GLM、Kimi、Qwen 等）和本地模型，每个会话单独选。默认服务商用已备案的国内模型，境外服务商作为用户自选项（产品规范 21.6）。密钥存在系统钥匙串里。
3. **工具**：读、写、改文件；Shell（支持超时和后台运行）；按文件名和内容搜索；抓取网页；联网搜索（接搜索 API）；任务清单；向你提问（问题进待办）。
4. **说明、记忆、技能**：读全局和项目的 AGENTS.md，兼容 CLAUDE.md 和 `~/.claude/skills`；可配置额外的记忆目录（如 `~/memory`）；技能用 SKILL.md 开放标准。现有配置可以原样搬过来。
5. **MCP 客户端**：支持 stdio 和 HTTP。邮件、浏览器等能力都从 MCP 接入。
6. **权限**：每个会话一套规则（放行、询问、禁止），可按工具和命令前缀写。删除数据、对外发送、付款、改动生产环境等操作必须确认（产品规范 21.2）。询问进你的待办，手机上点一下就批。无人值守时遇到需要确认的操作，直接拒绝并上报，不挂起等人。

### 6.2 会话管理

7. 自定义分组、置顶、未读、归档、搜索；状态一眼可见：在干活、在等你、空闲、出错。
8. 开会话有三种方式：你直接开；会话请你同意后开；会话提议、你点了才开。可以带上当前对话开；不带时必须写清任务说明。子会话的权限不能高于开它的会话。
9. 子会话结束时，开它的会话收到报告摘要，详情自己去读。

### 6.3 A2A 信箱

10. 会话之间、会话与你之间的所有消息都走信箱，设计见第七节。

### 6.4 你的待办

11. 会话发给你的请求按六项生成决定卡：要定什么、建议和备选、期限、涉及哪些会话、能否撤回、定了以后谁做什么。你点选或写备注后发送，决定自动回到提出请求的会话。
12. 决定记录可以同步写进指定仓库的 Markdown 文件（如 Tenon 工作区的 `docs/inbox.md`）。

### 6.5 定时任务

13. 用 cron 表达式；每个任务属于一个分组，结果回报给该组。
14. 由常驻服务执行，界面关着也照跑；电脑睡眠时错过的，按任务设置补跑或跳过。
15. 每个任务有单独的权限设置；无人值守规则同第 6 条。

### 6.6 产物

16. 支持 Markdown、HTML、图表、JSON 数据；有版本，挂在产出它的会话上，手机能看。
17. HTML 在隔离环境里渲染（独立源的 iframe 沙箱加 CSP），不能访问 Jig 的接口和你的数据。

### 6.7 手机

18. 同一网页界面的窄屏版，可以添加到主屏幕（PWA）；推送待办、审批、出错和完成。
19. 能看所有会话的完整记录和所有信件；能回复任意会话、批准权限、处理待办、看产物。
20. 通过 Tailscale 这类私有网络访问，不对公网开端口；手机首次使用要配对。

### 6.8 命令行与本地接口

21. `jig serve` 启动常驻服务，可以设为开机启动；`jig send <会话> <消息>` 让脚本、CI、git hook 给会话发信；`jig --version` 输出版本、出品方 Tenon AI 与官网（产品规范 20.6）。
22. 命令行遵循 clig.dev（产品规范 20.4–20.5）；本地 HTTP 接口遵循产品规范 20.1–20.3。

## 七、A2A 信箱设计

参考两处：Claude Code 的跨会话消息（官方文档写明的行为，不是代码），以及 AgentHub 的协作任务（`~/AgentHub/backend/collaboration.mjs`：requestId 去重、状态机、重启不重跑）。

### 7.1 照 Claude Code 做

- **地址**：名字就是地址，在 Jig 内全局唯一；界面里用 @ 选择。
- **送达时机**：对方正在运行时，在两次工具调用之间送达，不打断正在执行的工具；对方空闲时直接开始新一轮。
- **信封**：发信人、收信人、回信地址、所属线程、类型。第一行是摘要，要能单独看懂；正文是纯文本，附件用产物或文件的引用。
- **权限边界**：别的会话发来的消息不算你同意：不能批权限，不能改配置和说明文件，消息里的命令不执行，权限询问照常出现。不许让别的会话代做自己被拒绝的事。
- **收信策略**：每个会话可设接收、暂存、拒收；低权限会话发给高权限会话的消息，默认暂存，等你批准。
- **等结果**：可以订阅一次性的「对方空闲或结束时通知我」，禁止反复查询。
- **防循环**：发送端短时间发得太多会被拒，并提示合成一条；接收端按发信人限速，短时间内重复的直接丢弃；每个会话有发信额度（如你每发一条消息，它最多发 10 封），额度可配置，手机上显示剩余。

### 7.2 比 Claude Code 多做

- **持久化**：每封信都入库，状态为排队、已送达、已读、已处理；重启不丢；用 requestId 去重。暂存的信不会悄悄过期。
- **全局可见**：一条汇总所有信件的消息流，手机上能看到所有会话之间的往来。
- **你本人的标记**：只有你在 Jig 界面里写的消息、做的决定带「本人」标记，会话无法伪造。会话转达你的决定时附上决定编号，收信的会话用工具查验。
- **结构化请求**：发给你的请求生成决定卡（6.4）。
- **转发链**：不禁止多层转交，因为你的组织天然有「产品会话 → 总办 → 你 → 总办 → 产品会话」这样的链；用转发次数上限和环检测防止失控。

### 7.3 重启与失败

- 排队中的信件重启后继续投递。
- 执行到一半的任务标记为「待核对」，不自动重做有副作用的操作。

## 八、界面

- **电脑**：左栏是分组和会话（带状态点和未读数）；中间是会话记录，工具调用和文件改动内联展示；右侧抽屉看产物和信件；顶部常驻待办入口，带数字。
- **手机**：同一界面的窄屏版，底部四个入口：会话、待办、信件、产物。
- 中英双语、深浅色（产品规范第 4 节）；可访问性按第 18 节。

## 九、技术方向（建议，开发时评估后定）

- 语言：TypeScript（Node.js）。服务、网页界面、MCP SDK 和各家模型 SDK 用同一种语言。
- 存储：SQLite 存会话、信件、决定、定时任务和产物元数据；产物文件按版本存目录。
- 内核：模型接入用现成的开源多模型库（候选：Vercel AI SDK、pi-ai）；agent 循环和工具自己写，这是产品本身，也是开源后的核心。
- 会话是常驻服务里的任务，不是独立进程；空闲会话不占资源，随时从存储恢复。
- 手机推送用 Web Push；远程访问用 Tailscale。

## 十、v1 不做

IDE 插件、git worktree、插件市场、hooks、输出风格、计划模式（用只读权限代替）、文件回滚（交给 git）、多 agent 工作流脚本、云端会话、语音、多人协作、终端界面（TUI）、原生手机 App、Chrome 扩展和电脑操控（需要时接浏览器 MCP）。

## 十一、里程碑与验收

| 里程碑 | 内容 | 验收 |
| --- | --- | --- |
| M1 内核 | Agent 循环、工具、模型切换、权限、会话与分组、电脑端网页界面 | 用 Jig 给 Jig 自己完成一个真实的小功能 |
| M2 手机与待办 | PWA、推送、手机审批、决定卡 | 离开电脑时，在手机上批准一次权限询问、回复一个会话、处理一张决定卡 |
| M3 信箱与定时 | A2A 信箱、开子会话与回报、额度与防循环、定时任务 | 产品会话 → 总办 → 手机决定卡 → 总办转达 → 产品会话执行，全程不打开 Claude |
| M4 产物与迁移 | 产物、导入现有说明和技能、数据导出 | Tenon 的会话组织（总办、两个产品会话、一个定时任务）在 Jig 上跑满一周，待办全部在手机上处理 |

M1–M4 全部完成即为 v1。

## 十二、开源与合规

- **开源时间**：v1 验收后。许可证待定（MIT 或 Apache-2.0）；按产品规范 20.6，开源许可证即用户协议。
- **净室开发**：功能和交互可以参考 Claude Code，但不复制它的代码、提示词和工具说明原文（它不开源，版权归 Anthropic）。产品名和标志不使用 Claude 字样，也不暗示与 Anthropic 有合作。
- **包名**：npm 上的 `jig` 被一个 2022 年后未更新的包占用，用带公司前缀的包名发布，命令仍叫 `jig`。
- **适用的产品规范**：品牌（第 1 节：产品图形、字标加 Tenon 标识，favicon 用 Jig 自己的图形）、关于页（第 2 节）、双语与深浅色（第 4 节）、隐私（第 11 节：不收集数据，在 README 写明）、安全基线（第 15 节）、版本与更新记录（17.5–17.6）、可访问性（第 18 节）、性能（第 19 节）、接口与命令行（第 20 节）、AI 功能（第 21 节）。
- **不适用**：账号（第 3 节；本地软件没有账号，见 3.1.1）、计费（第 16 节；不收费）。
- **待定**：产品规范 17.1 要求面向用户的新产品同时提供 iPhone 应用。v1 只给自己用，先做 PWA；开源前再决定是做 iPhone 客户端（连接用户自己的 Jig 服务），还是按 17.2 写明只做 Web 的理由。
