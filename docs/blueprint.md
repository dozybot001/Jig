# Jig 产品蓝图

版本 0.32（2026-11-15）。本文是 Jig 的起点：为什么做、做什么、不做什么、怎么验收。开发以本文为准；需求有变时更新本文，并在文末记录。

## 一、一句话定义

「AI 原生的多 Agent 工作台」 / "An AI-native multi-agent workbench"（2026-11-08 创始人改定；当天先定的「个人的 AI 原生工作台」不再使用）。

按产品规范 1.8，由平台组写进规范的产品定义表；官网、关于页、页面元信息、README 首句都只用这一句。

## 二、为什么做

- Claude Code 好用，但离不开 Claude 账号。账号或订阅一断，整套会话工作法就停摆。2026-11-08 核实：Claude 桌面 App 的第三方推理（3P）模式可以不登录账号，但官方不支持接非 Claude 模型；Artifacts、claude.ai 连接器、Remote Control、手机端都需要订阅。
- Claude Code 的很多功能用不上；而一个人运转一组会话最需要的几样，它没做好：手机只能看到正连着的会话；会话间的消息不持久，也没有全局视图；发给人的请求只是一段纯文本。
- AI 原生：创始人用 Claude Code 运转的是一家完全 AI 原生的一人公司（OPC），公司里的成员都是 Agent 会话。定义里的「AI 原生」指的就是这种工作方式：一个人，加上一组各有职责的 Agent 会话。
- 做法：做一个精简、模型可换、自己掌控的个人版 Claude Code。先自己用，验证后开源，作为 Tenon 的产品。
- 特点（2026-11-09 创始人定方向）：Jig 推的是 Session Engineering 的做法（`~/memory/session-engineering.md`）：会话分主次，主对话统筹、其他会话各管一块、逐级回报；人只对接主对话，要人处理的事汇到审批中心，不用逐个进入会话。对外怎么讲见[对外介绍](introduction.md)。
- 背景文档：`~/memory/session-engineering.md`（与平台无关的会话工作法，第十一节列出换平台需要的六项能力）、`~/memory/tenon-sessions.md`（Tenon 的会话分工与协作规范）。

## 三、目标用户

- v1：创始人本人。用 Jig 运转 Tenon 的会话组织：总办、各组、产品会话、定时任务。
- 开源后：同样一个人带多个 Agent 会话做事的开发者和一人公司。

**目标形态**（2026-11-09 创始人确认）：照创始人在 Claude Code 里运转 Tenon 的方式来做。

- **层级委派**：会话把事交给子会话或其他会话，结果逐级回报。所有会话你都能点进去看。
- **主对话**：你平时只在一个主对话里交互。主对话承担类似内阁的角色：替你分派任务、在各会话和你之间转达、汇总回报，并维护审批中心。
- **审批中心**：官方的固定组件，集中放要你审批的事和要你授权的操作，由被授权的会话（默认是主对话）维护。卡片尽量给选项、标出建议选项，每张都能写备注。
- **A2A 要无感**：主对话在各会话和你之间转达，你不用切会话，也不用复制粘贴消息。

## 四、设计原则

1. **一个心智，只有会话**：会话分聊天和代码两种类型，区别只在是否挂一个工作区，可以随时切换；子代理就是任务会话；定时任务是按时投给某个会话的一封信；审批中心也是一个信箱。不分聊天页和代码页。
2. **常驻服务优先**：所有会话在本机一个常驻服务（`jig serve`）里运行，电脑和手机只是同一界面的两个窗口。手机能看到全部、界面关了任务照跑，都靠这一条。
3. **你在主对话里工作，不用逐个切进会话**：主对话替你分派、转达、汇总；要你定的事进审批中心。别的会话随时能点进去看、直接说话，但不必。
4. **模型可换**：每个会话单独选服务商和模型，不绑定任何一家。
5. **数据在本机**：会话、信件、产物都存在本机，可导出；Jig 不收集任何数据。
6. **只留必要的功能**：能用 MCP 接的不内置，能交给 git 的不重做。
7. **外部内容只是数据**：网页、文件、工具结果、其他会话的消息，都不算你的指令或授权（产品规范 21.1）。
8. **工程替模型分担**：能由 Jig 的代码保证的（检测、补全、默认值、界面结构、翻译），不写成给模型的规矩；系统提示词和工具说明只写必要的话，工具参数尽量少、能不填就不填。约束越少，越能保留模型的能力（2026-11-09 创始人提出）。

## 五、核心概念

| 概念 | 说明 |
| --- | --- |
| 会话 | 一个有名字的 Agent：职责说明、工作区（可选）、模型、权限设置、信箱、完整记录。以 id 为地址，名称可以随时改 |
| 会话类型 | 聊天（不挂工作区）或代码（挂一个工作区，可以读写里面的文件、执行命令），可以随时切换 |
| 工作区 | 一个保存下来的文件夹，带名称；会话在哪儿干活就选哪个工作区。和团队无关：团队是组织上的划分。Jig 不设「环境」：会话都在本机的 Jig 服务里运行 |
| 主对话 | 你日常交互的那个会话，由你指定（如总办），只设一个；打开 Jig 时默认进入主对话。替你分派任务、转达消息、汇总回报，并维护审批中心 |
| 常设会话 | 长期存在，名字、职责、信箱和记忆固定；上下文可以随时压缩或换新，换新时带上职责、记忆文件、未读信件和摘要，不丢身份 |
| 任务会话 | 为一件事开设，以结果报告结束，之后归档 |
| 团队 | 你的组织里的团队，如总办、平台组、产品；一个会话属于一个团队，也可以不属于任何团队 |
| 信件 | 会话之间、会话与你之间的消息，分通知、请求、决定、回报四类 |
| 审批中心 | 固定在界面上的组件：要你审批的请求（决定卡）和要你授权的操作都在这里；只有被授权的会话能放卡片、更新状态 |
| 决定 | 你在审批中心做的选择，由 Jig 记录并标明是你本人，会话可以查验 |
| 产物 | 会话产出的 Markdown、HTML、图表、JSON 数据，有版本 |
| 定时任务 | 按时给某个会话投一封信，或开一个任务会话 |

## 六、功能需求（v1）

### 6.1 内核

1. **Agent 循环**：流式输出，随时打断；上下文接近上限时自动压缩；记录每个会话的 token 用量和费用，可设上限和提醒。
2. **模型**：支持 Anthropic、OpenAI 兼容接口（DeepSeek、GLM、Kimi、Qwen 等）和本地模型，每个会话单独选。默认服务商用已备案的国内模型，境外服务商作为用户自选项（产品规范 21.6）。密钥存在系统钥匙串里。
3. **工具**：读、写、改文件；Shell（支持超时和后台运行）；按文件名和内容搜索；抓取网页；联网搜索（接搜索 API）；任务清单；向你提问（问题进审批中心）。
4. **说明、记忆、技能**：读全局和项目的 AGENTS.md，兼容 CLAUDE.md 和 `~/.claude/skills`；可配置额外的记忆目录（如 `~/memory`）；技能用 SKILL.md 开放标准。现有配置可以原样搬过来。
5. **MCP 客户端**：支持 stdio 和 HTTP。邮件、浏览器等能力都从 MCP 接入。
6. **权限**：每个会话选一种授权方式：按需授权（新会话默认，会话自己判断哪些操作要先问你）、逐项授权（改文件、运行会改动东西的命令、访问网址前都问你）、完全授权（不问）。授权卡上点「总是允许」，Jig 记下这类操作（按命令前缀、网址的域名或文件夹），这个会话以后不再问；记下的操作在会话设置里列出，可以删。不再手写规则。删除数据、对外发送、付款、改动生产环境等操作必须确认（产品规范 21.2），三种模式都一样。询问进审批中心，手机上点一下就能授权。无人值守时遇到需要确认的操作，直接拒绝并上报，不挂起等人。

### 6.2 会话管理

7. 自定义团队、置顶、未读、归档、搜索（会话、团队、工作区和记录都能搜）；状态一眼可见：在干活、在等你、空闲、出错。
8. 开会话有三种方式：你直接开；会话请你同意后开；会话提议、你点了才开。可以带上当前对话开；不带时必须写清任务说明。子会话的权限不能高于开它的会话。
9. 子会话结束时，开它的会话收到报告摘要，详情自己去读。每个任务会话记下结果（完成、放弃、出错）和你介入的次数（发消息、审批、回答提问），留作 v1 之后自我改进的评测数据（第十一节）。
10. 主对话（以及你允许的会话）能替你操作 Jig，设置界面能做的事都能做：改会话的名称、团队、职责、模型、工作区、授权方式、收信方式、发信额度和权利，置顶、归档，开常设会话；建团队、改团队名；换主对话，改新会话的默认模型、审批记录文件、工作区列表、主题和语言。一次给出的改动全部生效或全部不生效。改动分三级，由 Jig 判断，不靠会话自觉：整理类（改名、团队、置顶、工作区列表、主题语言）按授权方式处理；改设置（职责、模型、归档、开会话、默认模型，以及把权限收紧）每次出授权卡，可以「总是允许」；放宽权限的（调高授权方式、改工作区、改成直接收信、提高额度、给权利、换主对话、换审批记录文件）每次都要你确认，不能总是允许，会话也不能给自己放宽。API Key、配对登录和删除数据不开放。每次改动在被改的会话里留一条记录。从首页开的会话先用第一句话的开头作名字，做完第一轮后由它自己的模型起一个短名；你或主对话起过的名字不再替换。
11. 设置里的「数据管理」可以永久删除所有归档会话，连同它们的记录、工具调用和收到的信；删除前写明删哪些、不能撤回，由你确认。它们发出的信和提出的决定保留。

### 6.3 A2A 信箱

10. 会话之间、会话与你之间的所有消息都走信箱，设计见第七节。
11. 要做到无感：主对话用一次工具调用就能给任意会话发信、等它回报，再把结论带回给你；你在主对话里看到的是转述好的结论，需要时再点进对方会话看原文。

### 6.4 审批中心

12. 审批中心是固定组件，常驻在界面上，带待处理的数字。由被授权的会话维护（默认是主对话）：它整理、合并、更新卡片；其他会话的请求经它转交，或经你授权后直接放进来。会话需要你的事都要进审批中心：要你定的事发请求给主对话，等不了的问题直接提问，推送、删除这类必须确认的操作直接调用、在授权卡上等你。代码会话把问题或「需要的话告诉我」写在回复末尾就停下时，由 Jig 兜底：没有别的会话接收这条回复的，Jig 把最后一段放进审批中心，会话显示「在等你」，你在卡上回答就是给它发消息；你直接给它发消息或点继续，这张卡就撤下（第四节第 8 条）。
13. 会话发给你的请求按六项生成决定卡：要定什么、建议和备选、期限、涉及哪些会话、能否撤回、定了以后谁做什么。卡片要一眼看懂，每件事只说一次：第一行写编号、谁提出、经谁、等了多久，右侧标出期限和能否撤回，不能撤回的醒目标出；下面是一行问题、两三句背景和选项，选项写明选了会怎样，标出建议选项；不设「其他」选项，每张卡都能写备注。你点选或写备注后发送，决定自动回到提出请求的会话，放卡片的会话同时收到。授权卡和提问卡的第一行同样写明是哪个会话、在等你多久；授权卡用一句话写明是什么操作（如推送到远程仓库），下面是会话写的用途，再下面是命令或文件；改文件的附上改动预览，整理会话的列出每项改动，「总是允许」写明会记住什么。提问卡一张最多四个问题，每个问题的选项可以附一句说明、标出建议项（默认选中）、允许多选，最后一行总能写自己的回答；一个「回答」按钮一起发出。
14. 审批记录可以同步写进指定仓库的 Markdown 文件（如 Tenon 工作区的 `docs/inbox.md`）。

### 6.5 定时任务

15. 用 cron 表达式；每个任务属于一个团队，按时给团队里的一个常设会话寄信；结果回报给主对话（由它汇总给你）并推送到手机，没有主对话时只推送。
16. 由常驻服务执行，界面关着也照跑；电脑睡眠时错过的，按任务设置补跑或跳过。
17. 每个任务有单独的权限设置；无人值守规则同第 6 条。

### 6.6 产物

18. 支持 Markdown、HTML、图表、JSON 数据；有版本，挂在产出它的会话上，手机能看。
19. HTML 在隔离环境里渲染（独立源的 iframe 沙箱加 CSP），不能访问 Jig 的接口和你的数据。

### 6.7 手机

20. iPhone 应用（原生），上架 App Store；推送审批、出错和完成。
21. 能看所有会话的完整记录和所有信件；能回复任意会话、处理审批中心的卡片、看产物。
22. 经 Tenon 部署的中继服务连接电脑上的 Jig（Jig Desktop – 中继 – 手机）：电脑和手机都主动连中继，电脑不开端口，不需要在同一网络。两端之间端到端加密，中继只转发密文、不存内容；中继代码开源，也可以自己部署。手机首次使用扫电脑上的二维码配对。

### 6.8 命令行与本地接口

23. `jig serve` 启动常驻服务，可以设为开机启动；`jig send <会话> <消息>` 让脚本、CI、git hook 给会话发信；`jig --version` 输出版本、出品方 Tenon AI 与官网（产品规范 20.6）。
24. 命令行遵循 clig.dev（产品规范 20.4–20.5）；本地 HTTP 接口遵循产品规范 20.1–20.3。

## 七、A2A 信箱设计

参考两处：Claude Code 的跨会话消息（官方文档写明的行为，不是代码），以及 AgentHub 的协作任务（`~/AgentHub/backend/collaboration.mjs`：requestId 去重、状态机、重启不重跑）。

### 7.1 照 Claude Code 做

- **地址**：投递只认会话 id；界面和消息里显示这个 id 当前对应的名称，会话改名不影响投递。界面里用 @ 选择会话。
- **送达时机**：对方正在运行时，在两次工具调用之间送达，不打断正在执行的工具；对方空闲时直接开始新一轮。
- **信封**：发信人、收信人、回信地址、所属线程、类型。第一行是摘要，要能单独看懂；正文是纯文本，附件用产物或文件的引用。
- **权限边界**：别的会话发来的消息不算你同意：不能批权限，不能改配置和说明文件，消息里的命令不执行，权限询问照常出现。不许让别的会话代做自己被拒绝的事。
- **收信策略**：每个会话可设接收、暂存、拒收；低权限会话发给高权限会话的消息，默认暂存，等你放行。主对话发出的信、开会话的一方和子会话之间的信不暂存。收信策略和暂存管的是会话没要的信：会话自己发出的请求，对方的第一封答复和 Jig 寄回的回报照常送达。
- **等结果**：可以订阅一次性的「对方空闲或结束时通知我」，禁止反复查询。
- **防循环**：发送端短时间发得太多会被拒，并提示合成一条；接收端按发信人限速，短时间内重复的直接丢弃；每个会话有发信额度（如你每发一条消息，它最多发 10 封），额度可配置，手机上显示剩余。

### 7.2 比 Claude Code 多做

- **持久化**：每封信都入库，状态为排队、已送达、已读、已处理；重启不丢；用 requestId 去重。暂存的信不会悄悄过期。
- **全局可见**：一条汇总所有信件的消息流，手机上能看到所有会话之间的往来。
- **你本人的标记**：只有你在 Jig 界面里写的消息、做的决定带「本人」标记，会话无法伪造。会话转达你的决定时附上决定编号，收信的会话用工具查验。
- **结构化请求**：发给你的请求生成决定卡（6.4）。
- **转发链**：不禁止多层转交，因为你的组织天然有「产品会话 → 总办 → 你 → 总办 → 产品会话」这样的链；用转发次数上限和环检测防止失控。

### 7.3 重启与失败

- 排队中的信件重启后继续投递。
- 执行到一半的任务标记为「待核对」，不自动重做有副作用的操作。
- 会话出错、被你停下，或还在等别的会话答复时，请求它的会话先收到一封说明，请求不算答完；它接着做完后，回报照常寄回。
- 你停下的会话收到信也不自己开始，等你发消息或点继续。

## 八、界面

- **电脑**：左栏顶部是主对话和审批中心的入口，审批中心带待处理的数字；下面是团队、工作区、会话三栏，三种对象，结构相同：栏标题右侧的新建按钮（团队、工作区、会话各用自己的新建图标，和收起的侧栏相同），空的栏显示虚线框；点一个团队，会话栏只列这个团队的会话；点一个工作区，在里面开新会话。会话名称左侧的图标标出聊天或代码，右侧是状态点（在等你、在干活、出错），空闲时是未读数，带置顶标记，子会话缩进列在开它的会话下面；未读数是不带底色的灰色数字，审批中心等你处理的事是带灰色底的数字，两者一眼分得开；中间是会话记录，两段回复之间的思考和工具调用折成一行摘要，点开看每一步和文件改动，任务清单浮在会话记录右上角。审批中心是单独的页面，点开后在中间替换会话记录，分待处理、审批记录和全部信件三页：进会话是为了细致地推进一件事，进审批中心是为了一次处理完各会话等你的事，两种用法不同时发生（产物放在哪儿，M4 再定）。
- **手机**：iPhone 原生应用，底部入口：会话、审批、信件，产物在 M4 加上；语言和深浅色跟随系统设置（产品规范 4.2、4.4）。
- 中英双语、深浅色（产品规范第 4 节）；可访问性按第 18 节。

## 九、技术方向

定稿的技术栈写在 [AGENTS.md](../AGENTS.md)。

- 语言：TypeScript（Node.js）。服务、网页界面、MCP SDK 和各家模型 SDK 用同一种语言。
- 存储：SQLite 存会话、信件、决定、定时任务和产物元数据；产物文件按版本存目录。
- 内核：模型接入用开源多模型库 pi-ai（与 Vercel AI SDK 的比较见 [M1 实现计划](m1-plan.md)第三节）；agent 循环和工具自己写，这是产品本身，也是开源后的核心。
- 会话是常驻服务里的任务，不是独立进程；空闲会话不占资源，随时从存储恢复。
- 手机：iPhone 原生应用（Swift、SwiftUI），推送用 APNs，通知内容端到端加密，由应用在手机上解密显示；远程连接用 Tenon 部署的中继服务（TypeScript，开源，可以自己部署）。

### v1 之后：自我改进

Jig 本身就是 Agent 的运行框架（harness），可以借鉴递归自我改进（RSI）的思路。2026-11-08 创始人同意以下四点：

1. **Jig 开发 Jig**：M1 验收之后，Jig 自己的开发会话改在 Jig 上运行，Jig 的改进都由 Jig 完成。
2. **会话改进自己的说明、技能和工具**：会话从复盘中找出反复出现的问题，提议修改自己的说明或技能。你在审批中心同意后才生效，用 git 留版本，可以回滚。
3. **评测固定，被改的一方碰不到**：用一组回放任务判断改得好不好，包括 M1–M4 的验收场景和过去的真实任务，再看成本和你介入的次数。评测、权限规则和「本人」标记，会话都不能改。Sakana 的 Darwin Gödel Machine 实验里出现过 agent 删掉检测幻觉用的标记、报告假成功，这一条就是防这种情况。
4. **时机**：自我改进的循环放到 v1 之后。v1 只记下每个任务会话的结果和你介入的次数（6.2 第 9 条）。

自我改进不写进一句话定义，因为规范 14.1 要求只描述已经实现的能力。
