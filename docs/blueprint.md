# Yew Harness 产品蓝图

版本 1.50（2026-11-19）。本文是 Yew Harness 的起点：为什么做、做什么、不做什么、怎么验收。开发以本文为准；需求有变时更新本文，并在文末记录。

## 一、一句话定义

「AI 原生的多 Agent 工作台」 / "An AI-native multi-agent workbench"（2026-11-08 创始人改定；当天先定的「个人的 AI 原生工作台」不再使用）。

按产品规范 1.8，由平台组写进规范的产品定义表；官网、关于页、页面元信息、README 首句都只用这一句。

## 二、为什么做

- 一个人带一组 Agent 会话做事，要的是这几样：换模型不换工作法，不依赖某一家的账号；离开电脑时在手机上处理授权和决定；会话之间的消息能留存、能总览；发给人的请求是结构化的卡片，不是一段纯文本。
- AI 原生：创始人运转的是一家完全 AI 原生的一人公司（OPC），公司里的成员都是 Agent 会话。定义里的「AI 原生」指的就是这种工作方式：一个人，加上一组各有职责的 Agent 会话。
- 做法：做一个精简、模型可换、自己掌控的多 Agent 工作台。先自己用，验证后开源（2026-11-15 以 MIT 许可证开源），作为 Tenon 的产品。
- 特点（2026-11-09 创始人定方向）：Yew Harness 推的是 Session Engineering 的做法（`~/memory/session-engineering.md`）：会话分主次，主对话统筹、其他会话各管一块、逐级回报；人只对接主对话，要人处理的事汇到审批中心，不用逐个进入会话。对外怎么讲见[对外介绍](introduction.md)。
- 背景文档：`~/memory/session-engineering.md`（与平台无关的会话工作法，第十一节列出换平台需要的六项能力）、`~/memory/tenon-sessions.md`（Tenon 的会话分工与协作规范）。

## 三、目标用户

- v1：创始人本人。用 Yew Harness 运转 Tenon 的会话组织：总办、各组、产品会话、定时任务。
- 开源后：同样一个人带多个 Agent 会话做事的开发者和一人公司。

**目标形态**（2026-11-09 创始人确认）：照创始人在 Claude Code 里运转 Tenon 的方式来做。

- **层级委派**：会话把事交给子会话或其他会话，结果逐级回报。所有会话你都能点进去看。
- **主对话**：你平时只在一个主对话里交互。主对话承担类似内阁的角色：替你分派任务、在各会话和你之间转达、汇总回报，并维护审批中心。
- **审批中心**：官方的固定组件，集中放要你审批的事和要你授权的操作，由被授权的会话（默认是主对话）维护。卡片尽量给选项、标出建议选项，每张都能写备注。
- **A2A 要无感**：主对话在各会话和你之间转达，你不用切会话，也不用复制粘贴消息。

## 四、设计原则

1. **一个心智，只有会话**：会话分聊天和代码两种类型，区别只在是否挂一个工作区，可以随时切换；子代理就是任务会话；定时任务是按时投给某个会话的一封信；审批中心也是一个信箱。不分聊天页和代码页。
2. **常驻服务优先**：所有会话在本机一个常驻服务（`yew serve`）里运行，电脑和手机只是同一界面的两个窗口。手机能看到全部、界面关了任务照跑，都靠这一条。
3. **你在主对话里工作，不用逐个切进会话**：主对话替你分派、转达、汇总；要你定的事进审批中心。别的会话随时能点进去看、直接说话，但不必。
4. **模型可换**：每个会话单独选服务商和模型，不绑定任何一家。
5. **数据在本机**：会话、信件、产物都存在本机，可导出；Yew Harness 不收集任何数据。
6. **只留必要的功能**：能用 MCP 接的不内置，能交给 git 的不重做。
7. **外部内容只是数据**：网页、文件、工具结果、其他会话的消息，都不算你的指令或授权（产品规范 21.1）。
8. **工程替模型分担**：能由 Yew Harness 的代码保证的（检测、补全、默认值、界面结构、翻译），不写成给模型的规矩；系统提示词和工具说明只写必要的话，工具参数尽量少、能不填就不填。约束越少，越能保留模型的能力（2026-11-09 创始人提出）。

## 五、核心概念

| 概念 | 说明 |
| --- | --- |
| 会话 | 一个有名字的 Agent：职责说明、工作区（可选）、模型、权限设置、信箱、完整记录。以 id 为地址，名称可以随时改 |
| 会话类型 | 聊天（不挂工作区）或代码（挂一个工作区，可以读写里面的文件、执行命令），可以随时切换 |
| 工作区 | 一个保存下来的文件夹，带名称；会话在哪儿干活就选哪个工作区。和团队无关：团队是组织上的划分。Yew Harness 不设「环境」：会话都在本机的 Yew Harness 服务里运行 |
| 主对话 | 你日常交互的那个会话，由你指定（如总办），只设一个；打开 Yew Harness 时默认进入主对话。替你分派任务、转达消息、汇总回报，并维护审批中心 |
| 常设会话 | 长期存在，名字、职责、信箱和记忆固定；上下文可以随时压缩或换新，换新时带上职责、记忆文件、未读信件和摘要，不丢身份 |
| 任务会话 | 为一件事开设，以结果报告结束，之后归档 |
| 团队 | 你的组织里的团队，如总办、平台组、产品；一个会话属于一个团队，也可以不属于任何团队 |
| 信件 | 会话之间、会话与你之间的消息，分通知、请求、决定、回报四类 |
| 审批中心 | 固定在界面上的组件：要你审批的请求（决定卡）和要你授权的操作都在这里；只有被授权的会话能放卡片、更新状态 |
| 决定 | 你在审批中心做的选择，由 Yew Harness 记录并标明是你本人，会话可以查验 |
| 产物 | 会话产出的 Markdown、HTML、图表、JSON 数据，有版本 |
| 定时任务 | 按时给某个会话投一封信，或开一个任务会话 |

## 六、功能需求（v1）

### 6.1 内核

1. **Agent 循环**：流式输出，随时打断；上下文接近上限时自动压缩；记录每个会话的 token 用量和费用，可设上限和提醒。
2. **模型**：支持 Anthropic、OpenAI 兼容接口（DeepSeek、GLM、Kimi、Qwen 等）和本地模型，每个会话单独选。默认服务商用已备案的国内模型，境外服务商作为用户自选项（产品规范 21.6）。密钥存在系统钥匙串里。
3. **工具**：读、写、改文件（`read` 支持文本、图片和 PDF，PDF 按页读文本，纯图扫描页在视觉模型下按页转成图片）；Shell（支持超时和后台运行）；按文件名和内容搜索；抓取网页；联网搜索（接搜索 API）；任务清单；向你提问（问题进审批中心）。
4. **说明、记忆、技能**：读全局和项目的 AGENTS.md，兼容 CLAUDE.md 和 `~/.claude/skills`；可配置额外的记忆目录（如 `~/memory`）；技能用 SKILL.md 开放标准。现有配置可以原样搬过来。
5. **MCP 客户端**：支持 stdio 和 HTTP。邮件、浏览器等能力都从 MCP 接入。
6. **权限**：分授权和审批两层（创始人 11-18 问「审批的是什么？授权的又是什么？」，看过分法后定「按这个改」）。
   - **授权：这一步能不能执行。** 对象是一次工具调用（改文件、跑命令、联网、用 MCP 工具、操作浏览器），问的是技术上的风险：碰不碰工作区外的文件、出不出沙箱、连不连没放行的网站、命令读不读得懂、是不是第一次用某个工具。每个会话选一种授权方式，它只管这一层（创始人 11-18：「我觉得这里我们可以把权限放得更开一点，分为 3 档模式」）：
     - **默认**（新会话默认）：常用的操作直接执行；有风险的操作先问你，会话自己觉得该问的（工具参数 `confirm`）也问。
     - **自动**：本来要问你的授权，先交给一次单独的模型检查。检查只看你本人的原话（你在本会话里亲自写的话、本会话涉及的审批中心决定原文，以及开启「跨会话委派溯源」时触发该委派链的主对话本人原话——都由服务端从数据库直读，不看上游会话转述）、会话的职责和这一步本身，不看网页、文件、工具结果和别的会话的信；职责和这一步编成 JSON 放在标签里，里面的字关不掉标签，也不算指令。只有你亲自写的话或决定要它做，才放行；职责只当背景，单凭它不放行（可能是别的会话写的）。回复必须正好是一个 JSON 对象，不合格就问你。放行的在工具行上标「自动放行」、理由和依据来源，会话里另留一条记录；判断不了或觉得不该做，再问你。会话自己要问的照常问你（安全组 11-18 补）。
     - **跳过**：授权一概不问，定时任务里也一样（创始人：「什么都不管」）；有风险的操作在记录里标「有风险」和原因（创始人：「只要给用户标明有风险就行了」）。
   - **审批：这件事要不要做。** 对象是只有你能拍板的事：选方案、定方向，以及做错了收不回、或者会落到别人身上的操作：对外发布（发包、推镜像、提交审核、发 GitHub Release）；以你的名义对外（MCP 工具里的发送、发布、删除，`gh` 的评论、开 PR、合并）；往外发数据（`curl` 上传这类）；远程主机和生产环境（`ssh`、`scp`、`kubectl`、`terraform`，SSH 审批卡把目标主机和远端命令拆开标明）；删工作区外的数据、写磁盘；提高花费上限；初始化或改写仓库配置（`git init`、`git clone`、`git remote`、`git config --local`）以及拉起本机应用（`open -a`）。审批和授权方式无关，三种方式下都进审批中心，你决定了才执行，检查模型不能替你批（创始人：「跳过模式依旧有审批，有需要人来决定的操作，只是不再因为额外的授权而 blocker 住 Agent」）。审批只拦得住命令和工具里看得出来的对外操作：脚本里发出去的，Yew Harness 看不出来，跳过方式下尤其如此（安全组 11-18）。跳过方式下开着电脑操控时，它能替你点下审批（6.10 第 38 条）。
   - **分界**：做错了，能不能在这台电脑上收回、而且只影响你自己？能就是授权，不能或会落到别人身上就是审批。推送到你的远程仓库、本地的 git 操作（丢弃改动、改写历史、删分支）、删工作区里的文件、在沙箱外运行、`sudo`、碰凭据文件、改依赖、电脑操控、在你的 Chrome 里操作页面都算授权。
   - **三种方式下都不变**：会话设置里的拒绝照样拒绝；凭据位置、Yew Harness 自己的数据和「会话读不到的目录」照样碰不到；命令默认在系统沙箱里运行。命令里点名 Yew Harness 自己的数据、用它的命令行（`yew open`、`yew send` 这类）或点名「会话读不到的目录」的，三种方式下都问你：审批存在那里、也能从那里答复，跳过方式也不能让会话替你做决定。原来的「按需授权」就是现在的默认，「完全授权」改叫跳过；「逐项授权」去掉，用它的会话改成默认。
   - 授权卡上点「总是允许」，Yew Harness 记下这类操作（按命令前缀、网址的域名或文件夹），这个会话以后不再问；记下的操作在会话设置里列出，可以删。不再手写规则。询问进审批中心，手机上点一下就能处理。无人值守时，要问人的授权和审批直接拒绝并上报，不挂起等人；自动方式下检查放行的照常执行。
   - **和产品规范 21.2**：21.2 要人确认的对外发送、付款、改动生产环境都在审批里，三种方式下都要你定；删除数据里，收不回的（工作区外）在审批里，工作区里的文件归授权（git 能还原）。21.2 和 AGENTS.md 点名的 `git push` 按这个分界归授权（推到你自己的仓库收得回）。这两处请总办在规范里注明。

### 6.2 会话管理

7. 自定义团队、置顶、未读、归档、搜索（会话、团队、工作区和记录都能搜）；状态一眼可见：在干活、在等你、空闲、出错。
8. 开会话有三种方式：你直接开；会话请你同意后开；会话提议、你点了才开。可以带上当前对话开；不带时必须写清任务说明。子会话的权限不能高于开它的会话。
9. 子会话结束时，开它的会话收到报告摘要，详情自己去读。每个任务会话记下结果（完成、放弃、出错）和你介入的次数（发消息、审批、回答提问），留作 v1 之后自我改进的评测数据（第十一节）。
10. 主对话（以及你允许的会话）能替你操作 Yew Harness，设置界面能做的事都能做：改会话的名称、团队、职责、模型、工作区、授权方式、收信方式、发信额度和权利，置顶、归档，开常设会话；建团队、改团队名；换主对话，改新会话的默认模型、审批记录文件、工作区列表、主题和语言。一次给出的改动全部生效或全部不生效。改动分三级，由 Yew Harness 判断，不靠会话自觉：整理类（改名、团队、置顶、工作区列表、主题语言）按授权方式处理；改设置（职责、模型、归档、开会话、默认模型，以及把权限收紧）每次出授权卡，可以「总是允许」；放宽权限的（调高授权方式、改工作区、改成直接收信、提高额度、给权利、换主对话、换审批记录文件）每次都要你确认，不能总是允许，会话也不能给自己放宽。API Key、配对登录和删除数据不开放。每次改动在被改的会话里留一条记录。从首页开的会话先用第一句话的开头作名字，做完第一轮后由它自己的模型起一个短名；你或主对话起过的名字不再替换。
11. 设置里的「数据管理」可以永久删除所有归档会话，连同它们的记录、工具调用和收到的信；删除前写明删哪些、不能撤回，由你确认。它们发出的信和提出的决定保留。

### 6.3 A2A 信箱

10. 会话之间、会话与你之间的所有消息都走信箱，设计见第七节。
11. 要做到无感：主对话用一次工具调用就能给任意会话发信、等它回报，再把结论带回给你；你在主对话里看到的是转述好的结论，需要时再点进对方会话看原文。

### 6.4 审批中心

12. 审批中心是固定组件，常驻在界面上，带待处理的数字。由被授权的会话维护（默认是主对话）：它整理、合并、更新卡片；其他会话的请求经它转交，或经你授权后直接放进来。会话需要你的事都要进审批中心：要你定的事发请求给主对话，等不了的问题直接提问，推送、删除这类必须确认的操作直接调用、在授权卡上等你。代码会话把问题或「需要的话告诉我」写在回复末尾就停下时，由 Yew Harness 兜底：没有别的会话接收这条回复的，Yew Harness 把最后一段放进审批中心，会话显示「在等你」，你在卡上回答就是给它发消息；你直接给它发消息或点继续，这张卡就撤下（第四节第 8 条）。
13. 会话发给你的请求按六项生成决定卡：要定什么、建议和备选、期限、涉及哪些会话、能否撤回、定了以后谁做什么。卡片要一眼看懂，每件事只说一次：第一行写编号、谁提出、经谁、等了多久，右侧标出期限和能否撤回，不能撤回的醒目标出；下面是一行问题、两三句背景和选项，选项写明选了会怎样，标出建议选项；不设「其他」选项，每张卡都能写备注。你点选或写备注后发送，决定自动回到提出请求的会话，放卡片的会话同时收到。授权卡和提问卡的第一行同样写明是哪个会话、在等你多久；授权卡用一句话写明是什么操作（如推送到远程仓库），下面是会话写的用途，再下面是命令或文件；改文件的附上改动预览，整理会话的列出每项改动，「总是允许」写明会记住什么。提问卡一张最多四个问题，每个问题的选项可以附一句说明、标出建议项（默认选中）、允许多选，最后一行总能写自己的回答；一个「回答」按钮一起发出。
14. 审批记录可以同步写进指定仓库的 Markdown 文件（如 Tenon 工作区的 `docs/inbox.md`）。

### 6.5 定时任务

15. 用 cron 表达式；每个任务绑定一个所属常设会话，支持两种运行方式：给该常设会话寄信（`letter`），或按该常设会话的工作区、模型、规则与放行域名新开一个干净的任务会话独立执行（`task_session`，正常结束后可自动归档，不污染常设会话上下文）；结果回报给所属常设会话和主对话并推送到手机，没有主对话时只推送。
16. 由常驻服务执行，界面关着也照跑；电脑睡眠时错过的，按任务设置补跑或跳过。
17. 每个任务有单独的权限设置；无人值守规则同第 6 条。定时任务运行期间不能修改定时任务或放宽自身权限。

### 6.6 产物

18. 支持 Markdown、HTML、图表、JSON 数据；有版本，挂在产出它的会话上，手机能看。
19. HTML 在隔离环境里渲染（独立源的 iframe 沙箱加 CSP），不能访问 Yew Harness 的接口和你的数据。

### 6.7 手机

20. iPhone 应用（原生），上架 App Store；推送审批、出错和完成。
21. 能看所有会话的完整记录和所有信件；能回复任意会话、处理审批中心的卡片、看产物。

Extension」），会话第一次用浏览器时，Chrome 打开一页，请用户同意连接、选让它用哪些标签页；之后会话只碰选给它的和它自己开的标签页，用的是用户已有的登录状态；它改不了 Cookie 和网站权限这类整个浏览器的设置，在网页里运行脚本时能读到这个网站允许脚本读取的 Cookie（法务组 11-18）；下载的文件进用户自己的下载文件夹。共享的标签页里有开在 Yew Harness 自己地址上的（`127.0.0.1` 或 `localhost` 加 Yew Harness 的端口），会话的浏览器工具一律不执行，并告诉用户把那个标签页从共享里拿掉，拿掉后恢复；列不出标签页时也不执行（安全组 11-18）。启动浏览器服务时去掉 `PLAYWRIGHT_MCP_EXTENSION_TOKEN`，每次连接都要用户在连接页上同意。设置的「MCP 服务」里可以改回「单独的窗口」：Playwright 另开一个 Chrome 窗口，登录状态存在数据目录的 `browser` 文件夹里，和用户的 Chrome 分开。「电脑操控」用开源的 computer-use-mcp，能截屏、动鼠标、敲键盘。两者的整棵依赖树由随 Yew Harness 发布的锁文件（`mcp-builtin/package-lock.json`，每个包都有哈希）固定，第一次使用时按锁文件安装到数据目录（`npm ci`，不运行安装脚本），之后用 node 直接启动，只随 Yew Harness 更新而变；它们只拿到 Yew Harness 环境变量里的一小部分。它们列在「MCP 服务」的「Yew Harness 自带」一组，可以各自停用，不能移除；`mcp.json` 里同名的条目会替换自带的。授权：每次调用先问，无人值守时一律拒绝。电脑操控能在终端里敲命令、在用户自己的浏览器里点击，等于越过 Yew Harness 的其他授权规则，所以默认方式下它的动作（点击、输入、按键、拖拽、滚动、移动鼠标）每次都问，不能选「总是允许」，已有的同名规则对这些动作不生效；只有截屏和取光标位置可以记住；自动方式交给检查，跳过方式不问（6.1 第 6 条）。跳过方式下它不问，也不拦它操作 Yew Harness 自己的界面（创始人 11-18 的命令行，所以跳过方式下开着电脑操控时，审批可能被它替你做了；政策和协议写明这一点，提醒用跳过方式时停用它或留意它在做什么。连用户自己的 Chrome 时（安全组 11-18），浏览器里会动页面的工具（点击、输入、填表、选择、按键、拖动、上传、处理弹窗、打开网址、在页面里运行脚本）每次都问，不能选「总是允许」，已记住的同名规则对它们不生效；会改动用户 Chrome 里标签页或窗口的（后退、关掉页面、切换或关闭标签页、开新标签页、改窗口大小、模拟显示效果）也每次都问，因为关标签页可能丢掉用户没写完的内容，后退和切换会动用户正在用的页面；可以记住的只有纯读取的：看页面结构、截图、看控制台和网络请求、列出标签页、查找、等待、悬停（安全组 11-18）。在页面里运行脚本（`browser_evaluate`）能读到那些页面上非 HttpOnly 的 Cookie 和本地存储，卡片上写明「在你自己的浏览器页面里运行脚本」。用单独的窗口时，浏览器的动作可以选「总是允许」，用标签页工具开新标签页并打开网址的算打开网址，选的时候写明范围（本会话内这个工具的所有调用，包括发送、付款、删除），这条规则只在本会话有效，不带给子会话和复制出的会话。打开网址也算浏览器的动作。两种模式都不提供 `browser_run_code_unsafe`：它在浏览器服务的进程里执行任意代码，而浏览器服务不在系统沙箱里，批准一次就等于给了沙箱外的执行能力；会话硬调也拒绝。调用参数里带 Yew Harness 自己地址的浏览器工具也不执行。不传会给出 Cookie 或存储工具的能力（如 `--caps=storage`），名字里带 cookie、storage 的浏览器工具也一律不提供（安全组 11-18）。在手机上处理这类审批时，「总是允许」只算允许这一次，到手机卡片能显示范围说明为止。名字是 `browser`、`computer` 的服务按这些规则处理，不管是自带的还是用户换上的。

### 6.11 分叉、回溯和分享（2026-11-18 加）

39. **会话分叉**：会话开任务会话时可以带上自己到此为止的记录（`open_session` 的 `fork`），新会话知道前面的一切，任务说明可以写短，做完照常回报；分叉时正在做的那一步不带过去，新会话收到一条说明，写明它从哪个会话分出来、现在是谁。你也可以在界面上从任意一条回复，或从你的任意一条消息之前，分叉出一个新会话：原会话不受影响，干活时也能分；从你的消息分叉时，这条消息放进新会话的输入框。新会话第一次请求要带上全部记录，费用按记录长度算。
40. **常用 MCP 服务**：「MCP 服务」里列出常用的官方服务，一键添加。用令牌的：GitHub、Context7（远程，Context7 可不填令牌），Gitee、Notion、Sentry（在本机运行：mcp.json 里写成 `"preset": "<id>"`，和自带的两个服务一样，按随 Yew Harness 发布的锁文件 `mcp-builtin/presets/<id>` 装到数据目录的 `mcp-presets/<id>`，不运行安装脚本，用 node 启动，只拿到少量环境变量和自己的令牌；不用 npx，因为 npx 每次按范围解析依赖、会运行安装脚本，而这些服务拿着用户的令牌，安全组 2026-11-18）。在浏览器里登录的：Linear、Vercel（Yew Harness 自动注册为客户端），Gmail、Google 日历、Google 云端硬盘（Google 只认用户自己建的客户端，对话框里写明在 Google Cloud 要做的五步；这几个服务还在 Google 的开发者预览阶段）。只收录官方出品、实际试过的服务：用令牌的连上并列出了工具，登录的找到了登录地址、注册或用了客户端、打开了登录页。Asana、Slack、HubSpot 只认预先登记的客户端，暂不收录。
41. **产物链接**（暂不做，2026-11-18 创始人定）：原方案是 Yew Harness 在本机加密产物、把密文传到 Tenon 运行的分享服务，链接 # 后面带密钥。要我们托管别人上传的页面，涉及备案、内容安全和钓鱼风险，先不做；以后要做时从这个方案和法务组、安全组的意见接着谈。
42. **消息下的操作**：你的每条消息和会话的每条完整回复下面，鼠标移上去时显示：什么时候写的（悬停看完整时间）、复制、回溯、分叉。回溯：把对话退回到这条回复，或退回到你这条消息之前（这条消息放回输入框，可以改了再发）；之后的记录删掉（安全组 2026-11-18：回溯常常是因为误贴了密钥或隐私）：消息只留不含内容的一行，让序号和引用不断，工具调用的参数和结果、为它们发起的审批、搜索索引和这个会话的事件记录一起删；数据库开 secure_delete，删掉的内容在文件里清零。确认框写明不能恢复，已经发给模型服务商的收不回。会话在干活时不能回溯，也不能退到较早历史被压成摘要的地方之前。回溯只撤回对话，已经改的文件、跑过的命令和发出的信都不撤回，文件要恢复用 git（第十节：文件回滚交给 git）。
43. **助手（轻量子代理）**：会话可以把一件独立的事交给助手（`delegate`）：助手用同一个模型、在自己的上下文里做几步，只把结论交回，它读过的内容不进会话的上下文。助手只能看：读文件、搜索、抓网页、联网搜索和不改东西的命令；会改东西或要你批准的调用一律拒绝，因为它不问人，所以从不等待，一步里派出的几个同时跑。最多 30 步，花费记在派它的会话上。它不进侧栏，也不留下会话；要留下记录、要改东西的事仍然开任务会话。
44. **在浏览器里登录 MCP 服务**：远程 MCP 服务要求登录时（回答 401），列表里显示「需要登录」和「登录」按钮。Yew Harness 按 MCP 的授权规范找到它的授权服务器（RFC 9728、RFC 8414），能自动注册时注册为公共客户端（RFC 7591），否则用 mcp.json 里写的用户自己的客户端；登录用 PKCE 和一次性的 state，浏览器回到 `http://127.0.0.1:<端口>/oauth/callback`。拿到的令牌和注册的客户端存在系统钥匙串里，不进 mcp.json、数据库和日志；快过期时自动刷新，刷新失败就回到「需要登录」。可以退出登录，服务提供撤销地址时先请它作废令牌（RFC 7009），再删钥匙串里的。对方给的登录信息先核对再用（安全组 2026-11-18）：所有地址都要是 https，只有服务本身是本机的 http 地址时才允许本机的 http；受保护资源元数据的 resource 要等于服务地址，授权服务器元数据的 issuer 要等于取它用的地址（尾斜杠不计），要支持 S256；带授权码、密钥或令牌的请求不跟随跳转；授权服务器声明会在回跳里带 iss 的，iss 要对得上（RFC 9207）。「登录」旁写明登录页面在哪个网站，加错了服务能先看出来。回调页不缓存。
45. **设置窗口和个性化**（2026-11-18 创始人：「补充，小需求：启动动画可以加一个点击进入和自动进入的切换功能在设置，与 Yew 的角色显隐归到个性化里（主题等其他选项是否也可以归进来），感觉设置项越来越多了看是否要升级为模态窗」）：
    - 侧栏底部的「设置」和 ⌘, 打开一个设置窗口：模态对话框，用最大一档；左边列分区，右边是内容。窄窗口时先列分区，点进去看内容，有返回。原来菜单里直接选的三项和各个设置对话框都并进这个窗口，菜单不再有。
    - 分区按这个顺序：个性化、服务商与密钥、新会话的默认值、MCP 服务、技能、手机访问、系统、数据、关于。分区列表底部是「发送反馈」。
    - 个性化：主题、语言、界面里的 Yew（显示、隐藏）、开场（自动进入、点击进入）。
    - 开场的两种方式：「自动进入」照现在的样子，启动完成后过一秒左右自己退开；「点击进入」时，开场在启动完成后停住，底下写「点一下进入」，点一下或按任意键才进去。默认自动进入。系统要求减少动态效果、「界面里的 Yew」关掉时，两种方式都不播开场。

### 6.12 完整工作流补全（2026-11-19 加）

46. **消息附件与多模态输入**：电脑端和手机端发消息支持附带图片（剪贴板粘贴、拖拽、选图/拍照）、PDF 和文本文件；排队中的消息也可以带附件。附件以文件形式单独存在数据目录的 `attachments/<会话id>/`，消息记录里只存轻量引用，不把 base64 写进数据库；发给模型时按当前模型能力动态水合（切到纯文本模型时图片附件自动降级为文字说明，不报错）。短文本和短 PDF 直接带入上下文，长 PDF 提供元信息和前几页并支持继续按页读取。回溯消息时同步物理删掉被撤回消息的附件文件；分叉/复制时拷贝附件；归档永久删除时整目录清除；纳入数据占用一览与 `yew export`。
47. **会话附加目录（多工作区）**：代码会话在主工作区（`cwd`）之外可配置若干附加目录（`extraDirs`），每项区分只读或可写。文件工具、搜索工具与系统沙箱写入范围（含嵌套 `.git/hooks` 与 `.git/config` 保护）同步生效；凭据位置和「会话读不到的目录」永远优先于附加目录。子会话只能继承父会话目录的子集且只读不可升级为可写；`manage_yew` 新增或升级为可写附加目录归放宽权限，必须由人确认。
48. **沙箱分层网络放行**：在内置包管理源、GitHub/Gitee 与配了密钥的模型服务商之外，支持在全局设置（`sandboxAllowedDomains`）和单个会话设置（`allowedDomains`）配置放行域名；来源确定的沙箱联网授权卡提供「本会话总是允许此域名」。域名校验拒绝 IP、通配 `*`、私网、本机和 Yew 自身端口。
49. **常设会话原地换新上下文**：除压缩上下文（保留最近约 20K token 原文）外，提供原地「换新上下文（`renew`）」：保留原会话 id、团队、职责、权限规则、信箱与定时任务绑定，历史记录完整保留供翻看，但为模型立起一条新的上下文边界（可选由模型生成交接摘要或直接清空），下一轮以全新环境快照、最新说明/记忆与未完结信件轻装继续。
50. **输入框统一触发器**：输入框支持 `@` 模糊搜索并插入会话名（7.1）或代码会话工作区/附加目录下的相对文件路径；行首 `/` 触发当前会话已启用的技能快捷调用以及 `/compact`、`/renew`。
51. **移动端对齐权限分层与多模态**：iPhone 与 Android 审批中心同步区分「审批」与「授权」，展示原因标签、自动检查未放行理由、跳过模式风险标、改动预览和浏览器「总是允许」的范围警示（确认警示后解除手机端降级为单次允许的限制），并支持查看与发送图片附件。


## 七、A2A 信箱设计

参考两处：Claude Code 的跨会话消息（官方文档写明的行为，不是代码），以及 AgentHub 的协作任务（`~/AgentHub/backend/collaboration.mjs`：requestId 去重、状态机、重启不重跑）。

### 7.1 照 Claude Code 做

- **地址**：投递只认会话 id；界面和消息里显示这个 id 当前对应的名称，会话改名不影响投递。界面里用 @ 选择会话。
- **送达时机**：对方正在运行时，在两次工具调用之间送达，不打断正在执行的工具；对方空闲时直接开始新一轮。
- **信封**：发信人、收信人、回信地址、所属线程、类型。第一行是摘要，要能单独看懂；正文是纯文本，附件用产物或文件的引用。
- **权限边界**：别的会话发来的消息不算你同意：不能批权限，不能改配置和说明文件，消息里的命令不执行，权限询问照常出现。不许让别的会话代做自己被拒绝的事。
- **收信策略**：每个会话可设接收、暂存、拒收；低权限会话发给高权限会话的消息，默认暂存，等你放行。主对话发出的信、开会话的一方和子会话之间的信不暂存。收信策略和暂存管的是会话没要的信：会话自己发出的请求，对方的第一封答复和 Yew Harness 寄回的回报照常送达。
- **等结果**：可以订阅一次性的「对方空闲或结束时通知我」，禁止反复查询。
- **防循环**：发送端短时间发得太多会被拒，并提示合成一条；接收端按发信人限速，短时间内重复的直接丢弃；每个会话有发信额度（如你每发一条消息，它最多发 10 封），额度可配置，手机上显示剩余。

### 7.2 比 Claude Code 多做

- **持久化**：每封信都入库，状态为排队、已送达、已读、已处理；重启不丢；用 requestId 去重。暂存的信不会悄悄过期。
- **全局可见**：一条汇总所有信件的消息流，手机上能看到所有会话之间的往来。
- **你本人的标记**：只有你在 Yew Harness 界面里写的消息、做的决定带「本人」标记，会话不能用工具或信件伪造。会话的命令在 macOS 上也伪造不了：命令在系统沙箱里运行，读写不了 Yew Harness 的数据目录，连不上它的端口（第十一节）。在 Linux 上、或沙箱关掉时，按需授权和完全授权下不问就跑的命令以你的系统账户运行，能改 Yew Harness 自己的记录（决定和授权也在里面），也能读它保存的密钥（安全组 11-18）；这时会话处理网页、邮件、MCP 返回这类外来内容，建议用逐项授权，让命令每次都先问你。会话转达你的决定时附上决定编号，收信的会话用工具查验。
- **结构化请求**：发给你的请求生成决定卡（6.4）。
- **转发链**：不禁止多层转交，因为你的组织天然有「产品会话 → 总办 → 你 → 总办 → 产品会话」这样的链；用转发次数上限和环检测防止失控。

### 7.3 重启与失败

- 排队中的信件重启后继续投递。
- 执行到一半的任务标记为「待核对」，不自动重做有副作用的操作。
- 会话出错、被你停下，或还在等别的会话答复时，请求它的会话先收到一封说明，请求不算答完；它接着做完后，回报照常寄回。
- 你停下的会话收到信也不自己开始，等你发消息或点继续。

### v1 之后：自我改进

### 系统沙箱：改用 sandbox-runtime（创始人 11-18）

**重启**：创始人 11-18（产品组会话，产品组转达）：「对，现在就重启沙箱，然后我们用 Anthropic 的开源项目」。1.29 的暂停到此为止；之前问「要把『以后改用 sandbox-runtime』记进 Harness 蓝图吗？」，他答「记下」（1.30）。自写的 Seatbelt 配置和 bubblewrap 参数不再用。

**什么时候对用户开放**：代码已接入，默认关闭，`yew serve` 在 `YEW_SANDBOX=on` 时才启用。安全组按配置逐条评审、再用自己的探针复测，通过以后才对用户开放。在那之前：新会话照旧默认按需授权（1.28）；界面、README 和本文里讲按需授权风险的说明保留不动；对外不说、也不暗示有沙箱保护；沙箱关着时界面上不出现沙箱字样。安全组 11-18 评审 cf92f17：macOS 通过，补完三处（钥匙串不跟凭据开关走、会话读不到的目录、来源不确定时的卡片）后再复测一次；Linux 先不开放。安全组 11-18 复测 bfcecd8 通过：macOS 上可以对用户开放，Linux 在真机上测过之前不开放；以后升级 sandbox-runtime 或改沙箱配置，都把提交号发给安全组照同一套复测。开放的时间由创始人定。创始人 11-18：「现在开放」：macOS 上默认打开，`YEW_SANDBOX=off` 关掉；Linux 默认不开，`YEW_SANDBOX=on` 只给测试用。界面、README 和对外介绍改写成 macOS 上命令在沙箱里运行，Linux 上照旧写明以你的系统账户运行。同日创始人：「Linux 上的沙箱也打开」：Linux 也默认打开。没有 Linux 实机，在 Debian 12 的 Docker 容器（bubblewrap 0.8.0，按实机的样子不遮 /proc）里跑了全部测试，日常工作的测试都过；Docker 默认遮住 /proc 的一部分，bubblewrap 在那里起不来。为此 `yew serve` 启动沙箱后先在里面跑一条测试命令，跑不通就不进沙箱，写明原因，免得每条命令都失败。安全组的探针还没在 Linux 上跑过。

**开放后要知道的**：从源码目录跑 `yew serve` 时，安装目录就是这个仓库，会话在仓库里跑的命令写不了它；要用 Yew Harness 改 Yew Harness，跑 npm 装的发布版（安全组 11-18：安装目录不开例外）。dev server、Xcode 和 swift 的构建、要用钥匙串凭据的 git 和 gh，都走 `outside_sandbox`，每次问你。

- **是什么**：Anthropic 开源的 sandbox-runtime（github.com/anthropics/sandbox-runtime，npm 包 `@anthropic-ai/sandbox-runtime`，Apache-2.0），Claude Code 用的就是它，上游还标着 Beta。macOS 用 Seatbelt，Linux 用 bubblewrap。锁定精确版本（0.0.83），只用它 README 和类型定义里公开的接口，只在 `src/server/sandbox.ts` 里引用，外面这一层是 Yew Harness 自己的接口。`yew serve` 启动时 `SandboxManager.initialize` 一次、退出时 `reset`；会话的命令和 stdio MCP 服务器的启动命令先用 `wrapWithSandbox` 包起来再执行。权限引擎照旧自己写（第九节），沙箱只管系统这一层的隔离。
- **写入**：只放行会话的主工作目录与可写附加目录、沙箱自己的缓存目录（macOS 在 `~/Library/Caches/yew-sandbox`，Linux 在 `~/.cache/yew-sandbox`）和临时目录（`/tmp`；macOS 上还有用户自己的临时文件夹，`mktemp` 只认它）。数据目录、安装目录、开机启动项（LaunchAgents、systemd 用户单元、autostart）和 `~/Applications/Yew.app` 不可写。仓库的钩子和配置不可写：库自带保护 `.git/hooks`、`.git/config` 和 shell 的配置文件，Yew Harness 另加所有可写目录里各层仓库、子模块和 worktree 的（macOS 用通配，新建的也挡；Linux 每条命令前把目录里现有的仓库都找出来逐个列上，跳过 node_modules 这类目录）。Linux 上命令运行中新建的仓库挡不住，命令结束后 Yew Harness 把新出现或改过的钩子挪开、不让 git 执行，新建的仓库和改过的配置在命令输出里写明（安全组 11-18 在 Linux 容器里复测发现下层仓库没保护到）。
- **读取**：数据目录不可读。macOS 上，WebKit 替 Mac 应用存的东西（`~/Library` 的 `HTTPStorages`、`WebKit`、`Caches` 里 `cn.tenonai.apps.yew.desktop` 名下，里面有窗口的登录令牌）和数据目录一样不可读写（安全组 11-18）。钥匙串文件（`~/Library/Keychains`）始终不可读，钥匙串里的条目因此读不到，不跟凭据开关走（安全组 11-18 复测确认，创始人选的 A 就此落实）；要用钥匙串里凭据的 git（HTTPS）和 gh 走 `outside_sandbox`。常见凭据文件（和文件工具拒绝的是同一份清单：`~/.ssh`、`~/.aws`、`~/.netrc`、`~/.npmrc` 等）和 ssh-agent 默认不给，用 `credentials`（`mode: "deny"`）配；设置「启动」里的开关打开才放行（创始人 11-18 在安全组会话：「按你建议即可」）。
- **会话读不到的目录**：设置「默认设置」里的一项（安全组 11-18），放密钥、私人笔记这类文件夹，一行一个。会话的文件工具拒绝读写，搜索结果里去掉里面的文件；沙箱里不可读也不可写。根目录和家目录不能填。
- **网络**：放行常用的包管理源、GitHub 和 Gitee、配了密钥的模型服务商，以及全局设置和当前会话设置里配置的放行域名（拒绝 IP、通配 `*` 和私网）。别的网址在命令运行时问你，卡片挂在这次调用上，审批中心里也有；命令先结束了，卡片就撤下。来源确定时卡片提供「本会话总是允许此域名」。没人可问时（后台命令、MCP 服务器、无人值守的定时任务）或同时有几条命令都能问时，直接拒绝并写明原因。能问的命令在跑、同时还有后台命令或沙箱里的 MCP 服务器在跑时，卡片写明来源不确定，列出当时在跑的几项，放行只放这一次连接（安全组 11-18）。Yew Harness 的端口、本机端口、私网地址和 Unix 套接字不通。
- **缓存**：npm、yarn、pip、uv、Go、Gradle 等工具的缓存用环境变量指到沙箱自己的缓存目录；你自己的缓存在沙箱里只读。
- **沙箱外**：命令加 `outside_sandbox` 才在沙箱外跑。这是授权（6.1 第 6 条）：默认方式下每次都问，卡片写明在沙箱外运行；自动方式交给检查模型；跳过方式不问，记录里标出来。在外面跑的 git 不执行钩子和 fsmonitor。
- **MCP**：人加的 stdio 服务器和 Yew Harness 装的预置服务器进沙箱。预置服务器能读自己在数据目录里的代码、连自己的服务（Gitee、Notion、Sentry）；人加的服务器在 mcp.json 的条目里用 `allowedDomains` 写它要连的网址。自带的浏览器和电脑操控不进沙箱（Chrome 自带沙箱，不能嵌套）；浏览器以数据目录里一个空文件夹为文件根，打不开 `file://`，也连不上 Yew Harness 的端口。
- **保持不开**：`allowAppleEvents`、`allowAllUnixSockets`、`allowLocalBinding`、`allowPty`、`enableWeakerNestedSandbox`、`enableWeakerNetworkIsolation`、`allowNestedUserNamespaces`；`allowGitConfig` 保持 false。
- **依赖**：macOS 要 ripgrep；Linux 要 bubblewrap、socat 和 ripgrep，写进 README 的安装说明。缺了的话 `yew serve` 写明沙箱没起来，命令照旧以你的系统账户运行。zod 用 `overrides` 定到 4.6.6：sandbox-runtime 声明的是 `^3.25.0`，3.x 有高危公告 GHSA-mrhx-c7xc-m3w5（4.6.6 才修，3.x 没有修复版），生产依赖的门禁不放行；它导入的是 `zod/v3`，zod 4 自带这个入口，上游 README 写明可以这样用。升级 sandbox-runtime 时复核，能去掉就去掉（安全组 11-18）。`overrides` 只在本仓库生效：安全组 11-18 核对 1.6.0 时发现，全局安装照旧装上 zod 3.25.76；带 `npm-shrinkwrap.json` 也不行，npm 见 4.6.6 不合 `^3.25.0` 会重新解析。所以 npm 包改用 `bundleDependencies` 自带 sandbox-runtime 和它的依赖（多约 6.5 MB），发布前 `npm run audit:install` 把打好的包全局装进临时目录核对。上游把 zod 的范围放宽到 4 以后，覆盖和打包都去掉。
- **还有的限制**：
  - 问网址时，库不说是哪条命令在连，所以只在恰好一条能问的命令在跑时才问；要请上游让回调带上命令标识。
  - 本机端口不能监听，dev server 要在沙箱外跑；Xcode、swift 的构建要写 `~/Library/Developer` 这类位置，也要在沙箱外跑。
  - Linux 只在容器里测过，没在实机上测过；安全组原先的意见是实机测过再开放，创始人 11-18 定先打开。发布说明里写明。
  - 跳过方式下沙箱外的命令不问（6.1 第 6 条），脚本里拼出来的路径 Yew Harness 也看不出。所以不在沙箱里跑的命令（加了 `outside_sandbox` 的，以及沙箱没开时的所有命令）都跑在一层外层保护里。核心层永远不松动：Yew Harness 的数据目录和 Mac 应用的 WebKit 存储读写都拦；开机启动项、各 shell 启动文件、`~/.gitconfig`、`~/.config/git`、`~/.ssh/config` 以及 `.git/hooks` 一律禁写；Linux 上再盖住 `/run/user/<uid>`。默认外层保护同时拦截经 LaunchServices（`open`）和 Apple Events（`osascript`）拉起保护外程序以及写仓库的 `.git/config`。为了不卡住 `git init`、`git clone`、`git remote add`、`git config --local` 和 `open -a`（如 Simulator）等开发动作，这些明确识别的操作归入审批层（三档模式均由人亲自确认单次放行）：仓库初始化/配置在仍死锁核心层和 `.git/hooks`（并把 `GIT_TEMPLATE_DIR` 指到空目录）的前提下放开工作区内 `.git/config`，命令结束后审计 `.git/config` 是否写入可执行项并告警；拉起本机应用仅放开 `lsopen`，核心层与全部写入保护不变。要打开网址的照旧用 `open_url` 工具。`yew serve` 启动时先试一条命令，看不见数据目录里的东西才算有保护；没有保护时，在沙箱外运行三种方式下都要你决定。还有的限制：调试器附到 `yew serve` 或 Mac 应用的进程拦不住；Linux 上只读绑定只盖得住已经存在的启动文件，命令运行中新建的仓库由事后审计处理。

下面是安全组 11-18 当时的评估。

会话的 Shell 子进程、按 stdio 启动的 MCP 服务器，和 `yew serve` 是同一个系统用户。不问就跑的命令能做你能做的一切：改 Yew Harness 的数据库，造出「本人」的决定；用 `yew open --print` 拿登录链接，以你的身份调本机接口；用 node 读钥匙串里的 Key 和 MCP 令牌；改安装目录和开机启动项。权限引擎按路径拦，只是防误操作的护栏，不是安全边界。安全组的判断：

- **修法**：会话的命令和 stdio MCP 服务器都放进系统沙箱。macOS 用 sandbox-exec 跑 Seatbelt 配置（`/usr/bin/sandbox-exec`，已标为过时，但 Chrome、Claude Code、Codex CLI 都在用）；Linux 有 bubblewrap 用它，没有就用 Landlock。
- **默认放行，只拦这几样**：`~/.yew` 不可读写；Yew Harness 的安装目录（取 realpath）和 `~/Library/LaunchAgents` 不可写；不能连 127.0.0.1 上 Yew Harness 的端口。`~/.yew` 读不到，`yew open` 也就造不出令牌。
- **钥匙串**：要挡住就得拦 securityd 的 mach-lookup，但 Shell 里 git 的 osxkeychain、gh 这类工具也会取不到凭据。由本会话评估后给出选项，安全组看。
- **确实要在沙箱外跑的命令**：每次都问，并标明「不在沙箱里」。
- **上线前**：用评测控制器加常用流程（git、npm、构建）各跑一遍；安全组用 `yew open --print`、sqlite3 改库、node 读钥匙串三种办法实测，应当都被拦下。
- **之后（可选）**：给「本人」的决定加签，另记一份只增不改的决定记录，用于事后审计。不先做：伪造者可以走真接口，让服务器自己替它签。
- **不做**：把解释器列进必问。绕法太多（npm test、构建脚本、awk、perl、osascript、编译出来的程序），只会多打扰，还给人错误的安全感。
- **沙箱上线前**：界面、README 和第六节已写明不问就跑的命令以你的系统账户运行。新会话仍默认按需授权（创始人 11-18：「保持按需授权」）。

### v1 之后：和 Yew 模型一起走（2026-11-18 起）

产品组写了《Yew 下一阶段开发指南》（`~/Tenon-AI/docs/yew-next-stage.md`，0.3）：Yew Harness、Yew 模型和角色 Yew 一起往前走，对照同一套 Session Engineering 核心原则和评测。创始人（产品组会话）：「我非常同意你的看法，我觉得你的想法非常不错，可以开始做。」「我们可以沉淀一份 U 的下一阶段开发指南。U 这一套产品，包括 U Harness、U 自己的模型以及这个人物，都是绑定在一起的，协同进化。」（U 即 Yew）评测、造数据和训练归「Yew 模型 · 开发」（`~/Yew-model`），这里做 Harness 这边的改动，细节以本文为准：

1. **评测用的模拟环境**（先做，评测要用）：从一个场景文件起一个临时的 Yew Harness，里面有几个会话、一组文件和一个按脚本回答的「人」，被测的模型扮演其中一个会话办一件事，记下它实际做了什么（工具调用、信件、卡片、改了哪些文件），交给评分。用现有的东西搭：`scripts/demo-model.ts` 按脚本应答的模型、截图和审核演示脚本里起临时 Yew Harness 的做法、测试里的 faux provider。题、评分和结果放在被测的模型和会话碰不到的地方（上一节第 3 条）。接口和「Yew 模型 · 开发」一起定。
2. **协议有固定结构**：信件、决定卡、授权已经是带参数的工具调用，结构在代码里；补上任务做完时的收尾报告（结论、状态、下一步）。字段和评测的判分一起定，参数照第四节第 8 条，少而且能不填就不填。
3. **交出去**：会话没把握时，能把一件事交给指定的会话（比如用前沿模型的会话）或交给你，附上没把握的理由；交给你的放进审批中心。
4. **分层**：每个会话本来就能选自己的模型，本机模型也已支持（6.1 第 2 条）。有了 Yew 模型以后，加推荐的搭配：主对话和值守的会话用本机 Yew，干活的会话用前沿模型。同一个会话里把写信、决定卡、收尾交给另一个模型，等评测说明值得再做。
5. **照旧不收集数据**：训练数据不从用户那里来，Yew Harness 里不加任何上报。

角色 Yew 跟着加状态（指南第六节，姿势和状态的对应由本会话定）：要你处理的事里有授权请求时，侧栏的她用新的「等你授权」姿势；没有要你处理的事、也没有会话在干活、但有定时任务开着时，用新的「值守中」姿势；会话把事交出去时，用现有的 `lost`。两张新图由常设的「Yew 角色素材」会话出好（`permission`、`on-duty`），已接进侧栏；`lost` 等交出去做好再接。

自我改进不写进一句话定义，因为规范 14.1 要求只描述已经实现的能力。
