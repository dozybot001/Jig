# Jig M1 实现计划

版本 0.4（2026-11-08），创始人已确认。依据[产品蓝图](blueprint.md)第六、九、十一节；技术栈和开发约定的定稿写在 [AGENTS.md](../AGENTS.md)；各块借鉴哪些开源项目、能不能复制代码，见[可借鉴的开源项目](prior-art.md)。

## 一、范围与验收

- **范围**（蓝图第十一节）：Agent 循环、工具、模型切换、权限、会话与分组、电脑端网页界面。
- **验收**：用 Jig 给 Jig 自己完成一个真实的小功能。做法：在 Jig 的网页界面里开一个工作文件夹为 `~/Jig` 的会话，用国内模型，从需求到提交走完一个小功能（候选：把会话导出为 Markdown），包括读代码、改代码、跑 `npm run check`，经你批准后提交并推送；全程不打开 Claude Code。你在 Jig 里看过改动、确认功能可用，即验收通过，发布 0.1.0。

## 二、技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 语言与运行时 | TypeScript，Node.js 24 及以上 | 服务、界面、MCP SDK 和模型库用同一种语言；Node 24 能直接运行 `.ts`，开发时不需要构建；本机已装 24.19 |
| 存储 | Node 自带的 `node:sqlite`（SQLite 3.53） | 不用装原生模块；同步接口，支持 WAL 和 FTS5 全文搜索。备选 better-sqlite3 |
| 模型接入 | `@earendil-works/pi-ai` 1.5（MIT） | 见第三节 |
| 本地服务 | Hono + `@hono/node-server` | 体积小，用标准 Request/Response，自带 SSE |
| 实时推送 | SSE；界面的操作走普通 HTTP 请求 | 断线后按 `Last-Event-ID` 补发，M2 的手机网络切换也用得上；不需要 WebSocket |
| 网页界面 | React 19 + Vite 8 | 与 Yew、WeSaid 一致 |
| 密钥 | `@napi-rs/keyring` | 读写 macOS 钥匙串；开源后同样支持 Windows 和 Linux |
| 文件搜索 | 系统里的 ripgrep（`rg`） | 速度快，自动遵守 `.gitignore`；M1 先要求本机装好，开源前再定是否内置 |
| Markdown 渲染 | react-markdown | 默认不渲染原始 HTML，链接另做过滤 |
| diff | `diff`（jsdiff），服务端生成统一 diff | 界面自己渲染，少一个界面依赖 |
| 网页转 Markdown | htmlparser2 | 照 OpenCode 的转换写法，不需要浏览器环境 |
| 检查 | Biome、`tsc --noEmit`、`node --test` | 依赖少；测试用 Node 自带的测试运行器 |

## 三、模型接入库：pi-ai 与 Vercel AI SDK

2026-11-08 核对 npm 上的最新版本和两边的源码。

| | Vercel AI SDK 7.0（`ai`） | pi-ai 1.5（`@earendil-works/pi-ai`） |
| --- | --- | --- |
| 定位 | 通用的 AI 应用工具包，配套 Next.js、React 等网页框架 | 为编程 Agent 做的统一模型接口，同一作者的 pi 编程 Agent 建在它上面 |
| 维护 | Vercel；周下载约 4,500 万 | Earendil（作者 Mario Zechner）；周下载约 1,100 万；2026-10-01 发 1.0，11-02 到 1.5；2026-05 包名从 `@mariozechner/pi-ai` 改成现名 |
| 许可证 | Apache-2.0 | MIT |
| 国内模型 | 官方有 DeepSeek、Moonshot、Z.ai、阿里（Qwen）、MiniMax 的 provider | 内置 DeepSeek、Moonshot（国内）、智谱 Coding Plan（国内）、MiniMax（国内）、Qwen Token Plan（国内）、小米 MiMo；其他服务商和本地模型走 OpenAI 兼容接口，可按服务商指定思考参数的格式（deepseek、zai、qwen 等） |
| 模型目录 | 没有；只传字符串模型名时默认走 Vercel AI Gateway（境外） | 内置每个模型的上下文长度和价格，自动压缩的阈值和费用统计可以直接用 |
| 费用 | 只返回 token 数，价格表要自己维护 | 每次请求返回 token 数和费用 |
| 中途换模型 | 消息格式通用，思考内容的处理要自己写 | 已处理：换模型时丢掉旧模型的思考块，文字和工具调用照留 |
| 打断 | AbortSignal | AbortSignal；打断时已生成的部分可以放回上下文接着续 |
| 存储 | 消息可以序列化 | 上下文是纯 JSON，直接存进 SQLite |
| 密钥 | 每次调用自己传 | 可以接自己的凭据存储，接上钥匙串 |
| 测试 | 有模拟 provider | 有 faux provider，可以写确定性的 Agent 循环测试 |
| 数据上报 | 可选接 OpenTelemetry | telemetry 只是接口，没有导出端，不发送任何数据 |

**结论：选 pi-ai。** 两边都覆盖主要的国内模型；pi-ai 的抽象层级正好是「一次模型调用」，Agent 循环由我们自己写，而它自带的模型目录、费用统计、跨模型交接和可续接的打断，正好对应蓝图 6.1 第 1、2 条的要求，用 AI SDK 这些都要自己补。

Agent 循环也不依赖同一仓库的 pi-agent-core，而是照它的循环改写，原因见[可借鉴的开源项目](prior-art.md)第一节。

**风险和应对**：pi-ai 的维护团队小、版本发得快，包名改过一次。应对：锁定精确版本，升级时看更新记录再升；只在 `src/server/model/` 一处引用，其他模块不碰它的类型，需要时换成 AI SDK 只改这一层。

## 四、架构

```text
jig serve（一个常驻进程，只监听 127.0.0.1）
├── 本地接口（Hono）：REST + SSE，同时提供网页界面的静态文件
├── 会话运行器：每个在干活的会话一个 Agent 循环，都是进程里的异步任务
│   ├── 模型层：pi-ai，全项目唯一引用它的地方
│   ├── 工具：read、write、edit、glob、grep、shell、todo、ask_user、web_fetch
│   └── 权限：规则匹配，结果为放行、询问或禁止
└── 存储：~/.jig/jig.db（SQLite）；API Key 在系统钥匙串
```

- 会话不是子进程。空闲的会话只是数据库里的记录，收到消息时从存储恢复上下文（蓝图第九节）。
- **事件流**：每个标签页只开一条 SSE，因为本机走 HTTP/1.1，同一地址所有标签页合计只能开 6 条连接。
  - 侧栏用的会话状态是易失事件，断线重连后重读会话列表。
  - 会话记录的持久事件（消息、工具调用、审批、状态）带会话内序号，作为 SSE 的 `id`；重连时按 `Last-Event-ID` 从数据库补发。
  - 文字和思考的增量不入库；重连时补发一份进行中消息的快照。
  - 每 15 秒发一条保活注释；每个订阅者的发送队列有上限，溢出就断开，让它重连后重读。

## 六、Agent 循环

循环照 pi-agent-core 的 `agent-loop.ts` 改写（MIT，记进 `THIRD_PARTY_NOTICES.md`），每一步都落库，以便跨重启恢复。

1. **组装上下文**：
   - Jig 的系统提示词（自己写，不照搬 Claude Code）、会话的名称和职责说明、环境（日期、系统、工作文件夹、git 状态）。
   - 说明文件：先读 `~/.jig/AGENTS.md`；再从 git 根到工作文件夹逐级读，每层取一个，有 `AGENTS.md` 就用它，没有时读 `CLAUDE.md`；合计不超过 32 KiB。
   - `@文件` 引用最深 5 层，代码块里的不算，只导入项目根以内的文件；同一文件只载入一次。
   - 说明文件在会话中途改了，追加一条消息说明改动，不重写系统提示词，以免提示词缓存失效。
2. **调用模型**：流式转发给界面；回复写进 `messages`，同时累计 token 和费用。
3. **执行工具**：一批工具调用先逐个过权限，要询问的逐个问完：会话进入「在等你」，等你在界面里决定。然后执行：整批都是只读工具时并行，否则按顺序。结果按原顺序写回；被拒的调用以拒绝理由作为结果。
4. **运行中发来的消息**：你在会话干活时发的消息先存进数据库排队，送达前可以改或撤回。模型接口要求工具结果紧跟工具调用，所以排队的消息在一批工具结果写回之后、下一次请求模型之前送达，不打断正在执行的工具；会话空闲时直接开始新一轮（蓝图 7.1）。
5. **打断**：停止模型输出，结束正在运行的命令（整个进程组先 SIGTERM，3 秒后 SIGKILL）；已生成的部分保留，可以接着说。
6. **压缩**：上下文用到模型上限的 80% 或 20 万 token 时（先到为准），用当前模型把较早的记录压成摘要。保留最近约 2 万 token，不在工具调用和它的结果之间切开；服务商报上下文超长时，压缩后重试一次。每个会话可以改阈值。界面标出压缩的位置。
7. **重启**：服务重启后，原来在干活的会话标为「待核对」，执行到一半的工具调用标为待核对，不自动重做（蓝图 7.3）；你点「继续」才接着跑。

## 七、工具

| 工具 | 作用 | 默认权限 |
| --- | --- | --- |
| `read` | 读文本文件和图片。带行号，可指定范围；单次最多 2000 行或 50 KB，单行截到 2000 字符，截断时提示从哪一行接着读；二进制文件不读 | 工作文件夹内放行；之外询问；`~/.ssh`、`~/.jig` 等存放密钥的位置禁止 |
| `write` | 新建或整体重写文件；重写前必须在本会话读过 | 询问；可在会话里打开「直接改工作文件夹里的文件」 |
| `edit` | 替换一段文字。先精确匹配，不中再把空白、引号和破折号归一后匹配，仍须唯一；匹配到多处时报出次数并拒绝，另可选全部替换；保留原文件的换行符 | 同 `write` |
| `glob` | 按文件名找文件（`rg --files`） | 放行 |
| `grep` | 按内容搜索（`rg`，不读用户的 ripgrep 配置）；默认最多 100 条 | 放行 |
| `shell` | 用登录 Shell 在新进程组里执行命令；默认超时 2 分钟，最长 10 分钟；输出保留最后 2000 行或 50 KB，全文存临时文件；可以后台运行，结束时通知，之后读输出或结束它 | 询问；只读命令放行（见第八节）；可以按命令前缀记住放行 |
| `todo` | 维护本会话的任务清单，界面上常驻显示 | 放行 |
| `ask_user` | 向你提问，可带选项；M2 起问题进待办 | 放行 |
| `web_fetch` | 抓取网页并转成 Markdown，结果标为外部内容；手动跟随重定向，每一跳重新过权限，最多 10 跳；拒绝本机和私网地址；超时 30 秒 | 按域名询问，可以记住 |

`write` 和 `edit` 写入前比对文件的修改时间、大小和哈希，读过之后被改过就拒绝；同一文件的写入排队执行。

联网搜索和 MCP 客户端不在 M1，见第十二节。

## 八、权限

- **规则**：每个会话一套，写法为「效果 + 工具 + 路径或命令前缀」，效果分放行、询问、禁止；冲突时禁止优先，其次询问。新会话从设置里的默认规则复制一份。
- **Shell 命令**：按 `&&`、`||`、`;`、`|` 拆开逐段检查，每段都满足才放行；含命令替换、重定向写文件或解析不了的，一律询问。
  - 只读命令名单参照 Gemini CLI，排除 `find -exec`、`find -delete`、`rg --pre` 这类能执行或改文件的用法。git 的只读命令（如 `git status`、`git diff`、`git log`）只在工作文件夹内放行，因为仓库配置能让 git 执行别的程序。
  - 判断是否危险之前，先剥掉 `sudo`、`env`、`exec`、`bash -c`、`eval` 这类包装，最多剥 4 层。
  - 「允许并记住」按命令的前缀层级记，例如记住 `git status`、`npm run build`，而不是整条命令。
- **必须确认**：删除文件、`git push`、`git reset --hard`、发布包、`ssh`、`scp` 等远程操作、带请求体的网络请求，以及改工作文件夹以外的文件，每次都询问，只能「允许一次」或「拒绝」，不能记住（规范 21.2）。
- **审批**：审批卡显示在会话记录里，同时侧栏的状态点变为「在等你」。拒绝时可以写理由，理由作为工具结果交给模型。
- **消息不算批准**：会话记录里的任何文字都不能替你批准；只有你在界面里点的才算（蓝图 7.1）。

## 十、本地接口的安全

- 只监听 `127.0.0.1`，默认端口 4777，可以改。
- `jig serve` 启动时打印 `http://127.0.0.1:4777/#t=<一次性令牌>`；页面读到令牌后换成 HttpOnly、`SameSite=Strict` 的 Cookie，并用 `history.replaceState` 清掉网址片段（规范 15.1.3）。`jig open` 生成新令牌并打开浏览器。
- 校验 `Host` 只能是 `127.0.0.1` 或 `localhost` 加端口（防 DNS 重绑定）；带 `X-Forwarded-*`、`Forwarded` 头的请求一律拒绝。
- 所有接口都只接受同源请求：写请求校验 `Origin`，所有请求校验 `Sec-Fetch-Site`。同一主机的不同端口算同站，SameSite 挡不住本机其他端口上的页面，所以不能只靠 Cookie。
- Cookie 名带端口；Cookie 里是 HMAC 签名的会话令牌，换签名密钥即全部登出。
- 响应头带 CSP（只允许本站脚本，`frame-ancestors 'none'`）、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`。本机走 HTTP；M2 的手机访问经 Tailscale 的 HTTPS。
- 模型输出和工具结果都按不可信内容渲染：Markdown 转 HTML 后过滤，不执行其中的 HTML 和脚本；链接在新窗口打开，带 `noopener noreferrer`。

## 十一、命令行（M1）

- `jig serve [--port <n>] [--open]`：启动服务。
- `jig open`：打开网页界面。
- `jig key set|delete|list <服务商>`：管理 API Key；`set` 不回显输入，非交互环境从标准输入读，直接写进钥匙串。
- `jig --version`、`jig --help`。命令行按 clig.dev，输出只用英文（规范 20.4–20.6）。

## 十二、开发顺序

每一步带测试，`npm run check` 通过后提交并推送。复制第三方代码时，按[可借鉴的开源项目](prior-art.md)第二节记进 `THIRD_PARTY_NOTICES.md`。

1. **骨架**：`package.json`、`tsconfig`、Biome、`npm run check`；`jig --version`、`jig --help`。
2. **存储与会话**：SQLite 迁移；分组、会话、消息的存取和接口（RFC 9457 错误、分页）。
3. **模型层**：pi-ai 适配（服务商目录、自定义 OpenAI 兼容服务商和本地模型、钥匙串凭据、User-Agent）；`jig key`；faux provider 测试。这一步要用真实模型冒烟一次，需要你先用 `jig key set deepseek` 填一个 DeepSeek 的 Key（不要发在会话里）。
4. **Agent 循环**：流式事件、工具调用、打断与续接、运行中排队的消息、用量与费用、压缩、重启后待核对。
5. **工具**：第七节的九个工具。
6. **权限**：规则匹配、命令拆分、必须确认清单、审批的等待与恢复。
7. **本地服务**：路由、SSE 断线补发、一次性令牌换 Cookie、Host 和 Origin 校验、安全响应头。
8. **网页界面**：第九节全部内容。
9. **验收**：按第一节走一遍；通过后建 `CHANGELOG.md`，发布 0.1.0。

## 十四、验收步骤

M1 的九步已经完成（提交 1429a6d 至 dfc3672），下面是第一节的验收怎么走：

1. 存 DeepSeek 的 API Key：在终端运行 `jig key set deepseek`，粘贴 Key（不回显，只存进系统钥匙串）。
2. 在 `~/Jig` 运行 `npm run build:web`，再运行 `jig serve`，用它打印的链接打开网页界面。
3. 新建一个常设会话，工作文件夹填 `~/Jig`，模型选 DeepSeek V4 Pro。
4. 给它需求，例如：「给 Jig 加一个功能：把会话导出为 Markdown。做完运行 npm run check，通过后提交并推送。」过程中按审批卡决定；`git push` 会弹出必须确认的卡片。
5. 你在 Jig 里看过改动、确认功能可用，验收即通过。之后把 CHANGELOG.md 的「未发布」改成 0.1.0，`package.json` 升到 0.1.0，在 main 上打 `v0.1.0` 标签并推送（AGENTS.md「版本与更新记录」）。
6. 验收通过后，Jig 自己的开发会话改在 Jig 上运行（蓝图第十一节「v1 之后：自我改进」第 1 条）。

验收时 Jig 里的会话会直接改 `~/Jig`，这期间 Claude Code 的会话不改这个仓库，以免改到同一批文件。
