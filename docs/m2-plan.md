# Jig M2 实现计划

版本 0.5（2026-11-09）。依据[产品蓝图](blueprint.md) 0.13 第五、六、七、十一节；范围由创始人 2026-11-09 确认。技术栈和开发约定见 [AGENTS.md](../AGENTS.md)。

## 一、范围与验收

- **范围**：A2A 信箱、主对话、审批中心（决定卡、选项与建议选项、备注）、开子会话与回报、额度与防循环、`jig send`。只做电脑端；手机、推送和定时任务在 M3。
- **验收**：在电脑上走通：产品会话提请求 → 主对话放进审批中心 → 你点选 → 决定回到产品会话（主对话同时收到）→ 产品会话执行，全程不离开 Jig。具体步骤见第十二节。你走通后即验收通过，发布 0.2.0。

## 二、数据

迁移 2 新建两张表，给 `sessions` 加四列。

| 表或列 | 内容 |
| --- | --- |
| `letters` | 信件：发信方（会话、你本人、命令行或 Jig）、收信会话、类型（通知、请求、决定、回报）、摘要、正文、回复哪一封、所属线程、转发链、状态、送达时间、对应的会话记录条目 |
| `cards` | 决定卡：编号（#1、#2…）、放卡片的会话、提出请求的会话、要定什么、背景、选项、建议选项、期限、涉及的会话、能否撤回、定了以后谁做什么；状态（待定、已定、已撤下）；你的选择、备注和时间 |
| `sessions.parent_id` | 开它的会话，没有就是你直接开的 |
| `sessions.outcome` | 任务会话的结果：完成、放弃、出错 |
| `sessions.interventions` | 你介入的次数：发消息、批准权限、回答提问 |
| `sessions.letters_sent` | 你上次发消息之后，这个会话发了几封信，用于额度 |

- 会话选项新增：收信策略（接收、暂存、拒收）、发信额度、能否直接往审批中心放卡片。
- 设置新增：主对话是哪个会话、决定记录同步到哪个 Markdown 文件。
- 信件状态：排队、暂存（等你放行）、已送达、已处理（收信的会话这一轮做完了）、拒收、丢弃。

## 三、信件

### 3.1 收发

- **地址**：投递只认会话 id（蓝图 7.1）。会话用 `list_sessions` 查所有会话的 id、名称、职责和状态。
- **送达时机**：对方在干活时，在两次工具调用之间送达，和你排队的消息同一个时机；对方空闲或上一轮出错时，直接开始新一轮。对方处于「待核对」或被你停下时先排队，等你点继续或发消息。
- **归档**：会话归档时，排队和暂存给它的信作废并写明原因，等它回复的会话不再等；归档的会话不收新信，暂存给它的信也不能放行。
- **模型看到的格式**：每封信在收信会话的记录里是一条消息，用 `<letter>` 标签写明编号、类型、发信方和线程，结束标签带同一个编号，正文里伪造的标签不会和它混淆。界面把它显示成信件卡片，不显示成你说的话。
- **你本人的标记**：只有你在界面里发的消息和在审批中心做的决定算你本人。决定以 `<decision>` 消息送达；别的会话转述的决定编号，用 `check_decision` 查验。

### 3.2 回报与等结果

- **请求何时算答完**：会话读到别的会话的请求后，请求一直算没答完，直到它亲自答复（`reply_to` 写这封请求、类型不是请求），或者某一轮正常做完、Jig 替它寄出回报。
- **自动回报**：会话某一轮结束时，对每个还没答完的请求：
  - 这一轮正常结束，读到请求以后发出的请求也都有了答复：Jig 把它最后的回复作为回报寄回请求方，请求算答完。
  - 这一轮出错或被你停下：Jig 寄一封说明（出错原因或停下前的回复），请求仍未答完；它接着做完的那一轮，回报照常寄回。
  - 读到请求以后又向别的会话（或请求方本人）发了请求，还没答复：它的回复还不是结果，请求仍未答完；没有给请求方写过信的，Jig 寄一封说明。
  - Jig 寄出的回报和说明不会再触发自动回报，所以不会来回打转。
- **等结果**：`send_letter` 和 `open_session` 可以带 `wait`，一次工具调用就等到结果：对方回复这封信，或者对方这一轮结束（带回它最后的回复），最长等 30 分钟，超时后回报照常以信件寄到。对方发来的其他信不算回复，照常作为信件送达。不允许互相等：等的关系连成环时，拒绝这次等待，信照发。
- **交给等待的信**：回复交给正在等的工具调用后，跟着这次调用的结果写进记录；结果还没写下 Jig 就停了，重启后这封信重新作为信件送达。

### 3.3 收信策略

- 每个会话可设接收（默认）、暂存、拒收。暂存的信进审批中心，你放行或拒收，不会自己过期。
- 低权限会话发给高权限会话的信，默认暂存。权限从低到高：聊天会话、手动审批、自动审批、跳过审批。例外：主对话发出的信、开会话的一方和子会话之间的信、你本人的决定都不暂存（蓝图 7.1）。
- 收信方式和暂存都只管会话没要的信：你本人的决定、Jig 寄出的回报和说明，以及对收信会话还没答完的请求的第一封答复（类型是回报或通知），不受它们限制。这封答复让请求算答完，之后同一线程上的信照常暂存。
- `jig send` 发的信标为「来自命令行」，按外部内容对待，不算你本人。在会话的 Shell 里运行时（环境变量 `JIG_SESSION`），信算那个会话发的，受它的额度、限制和暂存规则管。
- 会话在 Shell 里运行 `jig` 命令（看版本和帮助除外），或者命令里写到密钥所在位置和 Jig 的数据目录，每次都要你确认，不能设为总是允许：会话应当用自己的工具发信，不能绕过上面的规则，也不能改 Jig 的数据。

### 3.4 防失控

| 规则 | 做法 |
| --- | --- |
| 发信额度 | 你每给一个会话发一条消息或做一个决定，它最多发 10 封信（主对话 30 封），会话设置里可以改；用完后发信被拒，并告诉会话等你的下一条消息 |
| 发送限速 | 一个会话每分钟给同一个会话最多发 3 封，超过的被拒，提示把内容合成一封；每分钟总共最多 20 封，主对话给每个会话各发一封也够用 |
| 重复丢弃 | 同一发信方发给同一会话、摘要和正文都相同、回复的也是同一封信的，10 分钟内只收第一封 |
| 接收限速 | 同一发信方 10 分钟内给同一会话最多 10 封，多的丢弃 |
| 转发次数上限 | 一条转发链最多 8 跳 |
| 环检测 | 同一条链里，一个会话第 3 次被转回时拒绝 |

- 转发链：会话因为收到信而开始的这一轮里发出的信，接在那封信的链上；你发消息或做决定开始的一轮从头算。
- Jig 寄出的自动回报和决定不占额度、不受限速，也不做重复检查：每份自动回报只回答一个请求。
- 欠着的自动回报记在数据库里：会话读到请求后 Jig 重启了，它下次做完一轮时照样寄出。
- 被拒或被丢弃的信，发信的会话会在工具结果里看到原因；信件列表里也能看到。

## 四、主对话

- 只设一个，在会话菜单里「设为主对话」，再点一次取消。打开 Jig 时默认进入主对话；首页仍用来开新会话。
- 主对话的系统提示词多一节：替你分派任务（发给常设会话，或开任务会话）；收到回报时用几句话告诉你结论；会话需要你定的事，整理成决定卡放进审批中心，合并重复的、更新变了的、撤下不再需要的；决定由 Jig 直接送回提出请求的会话，主对话不用转述。
- 其他会话的系统提示词写明主对话的名称和 id：要你定的事，发请求给主对话。
- 主对话换了，或者某个会话成了、不再是主对话，下一轮在记录里追加一条说明，系统提示词不重写（提示词缓存，和换权限模式的做法相同）。

## 五、审批中心

- **谁能放卡片**：主对话，以及你在会话设置里勾选的会话。只有它们能用 `post_card`、`update_card`、`withdraw_card`。
- **决定卡**：六项都要写清（产品规范之外，沿用 Tenon 会话规范 4.5）：要定什么、建议和备选、期限、涉及哪些会话、能否撤回、定了以后谁做什么；另有背景说明。选项最多 6 个，标出建议选项并默认选中；可以没有选项，这时你写备注作答。
- **你做决定**：点选项、写备注，点「发送」。Jig 记下决定（编号、选择、备注、时间，标为本人），送给提出请求的会话和放卡片的会话，再同步到决定记录文件（如果设了）。
- **决定记录文件**：设置里填一个 Markdown 文件的路径（例如 Tenon 工作区的 `docs/decisions.md`），每个决定追加一行。不改文件里已有的内容。
- **审批中心里还有**：所有会话正在等你的权限审批和提问，以及暂存待放行的信。审批和提问在这里处理，和在会话记录里处理是同一件事。
- **数字**：等你处理的总数：权限审批、提问、决定卡、待放行的信。网页标题也带这个数字。

## 六、开子会话与回报

- `open_session`：写名称和任务说明（必填）开一个任务会话，它的第一条消息就是这份任务说明，作为请求信送达。
- 子会话的权限不高于开它的会话（蓝图 6.2 第 8 条）：权限模式和规则照抄开它的会话；工作区只能是开它的会话的工作区或其中的子文件夹，或者不用工作区；模型默认相同，可以指定。
- 开会话按权限模式处理：手动审批时先问你；自动审批时直接开，除非会话自己标了要你确认；跳过审批时直接开。
- 子会话每一轮结束，回复按 3.2 自动寄回开它的会话，包括你直接在子会话里说话的那几轮；这一轮它已经给开它的会话寄过回报的，不再寄。任务会话用 `finish_task` 记下结果（完成、放弃、出错），之后它的最后一条回复就是结果报告。
- `open_session` 先检查任务说明能不能发出（长度、额度、限速、转发链），发不出就不开会话，直接告诉开它的会话原因。
- 每个任务会话记下结果和你介入的次数，留作 v1 之后的评测数据（蓝图第十一节）。
- 侧栏里子会话缩进列在开它的会话下面。

## 七、新增工具

| 工具 | 作用 | 谁有 | 权限 |
| --- | --- | --- | --- |
| `list_sessions` | 列出所有未归档的会话：id、名称、类型、分组、状态、职责的第一行，并标出主对话、开你的会话和你自己 | 所有会话 | 放行 |
| `send_letter` | 发信：收信会话 id、类型（通知、请求、回报）、摘要、正文、回复哪一封；可选 `wait` | 所有会话 | 放行，受第 3.4 节限制 |
| `check_decision` | 按编号查一个决定：要定什么、你的选择和备注、时间；未定或已撤下也照实说 | 所有会话 | 放行 |
| `open_session` | 开任务子会话，可选 `wait` | 所有会话 | 按权限模式 |
| `finish_task` | 记下任务结果：完成、放弃、出错 | 任务会话 | 放行 |
| `post_card` | 往审批中心放决定卡，可合并旧卡 | 主对话和授权的会话 | 放行 |
| `update_card` | 改一张待定的卡 | 同上 | 放行 |
| `withdraw_card` | 撤下一张待定的卡并写明原因 | 同上 | 放行 |
| `list_cards` | 列出待定的卡和最近的决定 | 同上 | 放行 |

工具说明都是 Jig 自己写的（AGENTS.md 净室开发）。

## 八、本地接口

- `GET /api/center`：审批中心的全部待办：决定卡、各会话等你的审批和提问、待放行的信。
- `POST /api/cards/:id/decide`：做决定（选项、备注），接受 `Idempotency-Key`。
- `GET /api/cards?status=decided`：最近的决定，分页。
- `GET /api/letters`：所有信件，新的在前，分页；可以按会话筛选。
- `POST /api/letters/:id/release`、`POST /api/letters/:id/refuse`：放行或拒收暂存的信。
- 设置里的 `mainSessionId`、`decisionLog`；会话选项里的 `receive`、`letterQuota`、`canPostCards`。
- 事件流新增三种全局事件：信件、决定卡、审批的变化，审批中心和信件列表据此实时更新；断线重连后重新读取。

## 九、命令行

`jig send [--kind notice|request|report] [--json] <会话> <消息>`：给会话发信。会话可以写 id 或名称；消息写 `-` 时从标准输入读。

- 直接写进本机的 Jig 数据库：服务没在运行时信件排队，服务启动后送达；服务在运行时 2 秒内送达（服务每 2 秒查一次命令行寄来的信）。
- 收信会话已归档或拒收时报错，退出码非 0；暂存时照常退出，并在标准错误说明要你在审批中心放行。
- 输出按 clig.dev：结果写标准输出，提示和错误写标准错误；`--json` 输出信件的 id、收信会话和状态。

## 十、界面（电脑端）

- **侧栏顶部**：「主对话」一行（设了才有，点开主对话）和「审批中心」一行（带数字），在「新建分组」和搜索之上。收起的侧栏里是两个图标，审批中心的图标带数字。
- **审批中心页面**：点「审批中心」后在中间替换会话记录（蓝图 0.9），分三页：
  - 待处理：先列在等你批准的权限和提问（会话停在那里），再列决定卡（有期限的按期限排在前面），最后是待放行的信。每张卡写明来自哪个会话，点会话名进那个会话。
  - 决定记录：你做过的决定，新的在前，带「本人」标记。
  - 信件：所有会话之间的往来，新的在前，显示时间、发信方 → 收信方、类型、摘要和状态，点开看正文。
- **会话记录**：收到的信显示为信件卡片（发信方、类型、摘要，正文可展开）；收到的决定显示为决定卡片（编号、选择、备注、本人）；发信、开会话、放卡片等工具调用在折叠摘要里计数，例如「发信 2 封」。
- **会话菜单**：设为主对话、不再作为主对话。
- **会话设置**：收信策略、发信额度（显示这一轮还剩几封）、能否直接往审批中心放卡片。
- **设置**：在「新会话的默认设置」对话框里加「决定记录文件」。
- 中英双语、深浅色、键盘操作和读屏按规范第 4、18 节；三页标签可以用左右方向键切换。

## 十一、开发顺序

每一步带测试，`npm run check` 通过后提交并推送。测试里不调用真实模型，用 faux provider。

1. **数据**：迁移 2；信件、决定卡的读写；会话新增字段和选项；全局事件。
2. **邮局**：发信的全部检查（地址、归档、收信策略、额度、限速、重复、转发链）；暂存的放行和拒收；决定卡的放、改、撤和做决定；决定记录文件。
3. **会话收发**：送达时机、信件格式、`list_sessions`、`send_letter`（含等结果）、`check_decision`、自动回报、系统提示词。
4. **主对话与审批中心的服务端**：主对话设置、卡片工具、本地接口。
5. **开子会话**：`open_session`、`finish_task`、权限上限、结果和介入次数。
6. **`jig send`**。
7. **界面**：第十节全部内容。
8. **验收**：按第十二节走一遍；通过后更新 CHANGELOG.md，发布 0.2.0。

## 十二、验收步骤

1. 重启 `jig serve`，刷新网页。
2. 把一个会话（例如「总办」）设为主对话；再开或选一个代码会话作为产品会话（例如工作区是 `~/Jig` 的「Jig · 开发」）。
3. 在产品会话里说：「有一件事要创始人定：……。按规矩发请求给主对话。」
4. 主对话收到请求，放一张决定卡进审批中心；侧栏的数字加一。
5. 打开审批中心，看六项是否写清，选一个选项、写一句备注，点发送。
6. 产品会话收到带「本人」标记的决定，照着执行；主对话同时收到。
7. 另外试一次：在主对话里让它开一个任务会话做一件小事并等结果，结果回到主对话。

- **0.5（2026-11-09）** 独立复审 A2A 后修正：请求在答复或正常做完之前一直算没答完，出错、被停下或还在等别人答复时先寄说明、结果随后寄回（原来出错的那封回报就把请求关了，之后的结果寄不回去）；只有回复这封请求、类型不是请求的信才算答复，等结果也只认回复这封信的信（原来对方发来的任何信都算）；子会话每一轮都向开它的会话回报；收信方式和暂存不管会话自己请求得到的答复；`open_session` 先检查任务说明再开会话；你停下的会话不被信件和每两秒的检查叫醒；压缩不改变「待核对」和出错的状态；交给等待的回复在结果写下前重启也不丢；归档时作废给它的信；会话在 Shell 里用 `jig` 命令或碰密钥和 Jig 数据目录时每次都要你确认，`jig send` 在会话里运行时算那个会话发的。
- **0.4（2026-11-09）** 复审 A2A 链路后修正：欠着的自动回报改为记在数据库里，重启后不丢；发送限速改为按收信会话计（每分钟 3 封，总共 20 封），主对话分派给多个会话时不被拦；重复检查把回复的是哪封信算进去，自动回报不做重复检查；低权限会话只有对收信方请求的第一封答复不暂存；等结果的一方，要等对方真的读到这封信才算对方答完。
- **0.3（2026-11-09）** 创始人定：审批中心改成单独的页面，替换中间的会话记录，不用右侧抽屉；第十节相应修改。
- **0.2（2026-11-09）** 第 1–7 步完成。实现时补了一处：自动回报只在会话这一轮没有亲自回信时才寄，等结果的一方直接拿到回复、不再另收回报；顺带修正了 M1 的提示词缓存问题（说明文件等变化后，提示词从下一步起就变了）。
- **0.1（2026-11-09）** 首版。
